# 冲销事项与个人收支统计设计

设计日期：2026-09-29。状态：已实现并完成隔离验证。

本设计承接用户确认的“先逐笔记录实际收付款，再手工组装冲销事项”的流程。数据、页面、查询、图表和导出按本文统一口径。

## 1. 目标与已确认边界

聚餐垫付后收回款项、代收多人收入后分发等业务，会同时放大现有账本的收入和支出。新增第五页“冲销与代收代付”，允许用户把多笔已存在的收入、支出关联成一个事项，在需要时按该事项的净额统计个人收支。

已确认规则：

1. 原始流水是实际收付款事实，继续决定账户余额、逐笔余额和资金路径。
2. 事项支持多笔支出对多笔收入，无须一笔对一笔匹配，也不限制收付款先后顺序。
3. 分为“支出冲销”和“收入冲销”，由用户选择方向。
4. 不设置“处理中 / 已结清”状态，不预测本人份额，不计算应收、应付或未结算金额。
5. 事项始终按当前关联的实际流水计算；用户可随时追加、移除或重新组合记录。
6. 统计日期自动取全部关联原始流水的最早日期；支出可按原分类分摊净额，收入及旧方式继承最早一笔主方向流水，不需要手工指定日期、起点或分类。
7. 支持跨账户、跨日期、跨月和跨币种；支持零净额、负支出和负收入。
8. 原始收付与冲销后收支是两个明确的统计口径，可以切换查看。

一笔原始流水最多属于一个事项，不拆分同一笔金额到多个事项。一件事采用一个统计日期；第一版的单分类规则由第 4 节的混合支出分类分摊扩展，同一事项可以贡献多个支出分类净额。

本功能不新增虚构的收付款，不生成 `adjustment`，不修改原流水的收入 / 支出类型。名称中的“冲销”表示统计归并，不用于替代已有的数据纠错和余额调整功能。

### 预算使用中的口径澄清

#### 2026-11-07：事项预算与负净收入（本轮实现）

事项预算统一以完整事项为单位：支出事项按“支出减返还”扣减承担预算，负净支出回补该预算；收入事项正净额仍通过收入分配进入一个或多个预算，成员收入不能另行分配；收入事项负净额按“分出减收入”扣减承担预算，不形成新的正收入额度。零净额不新增资金。原始收入/支出方向及个人收支的有符号净额保持不变。

事项增加可空 `budget_system_id`，表示整项消费或净亏损的明确承担预算，优先于成员标签；留空时支出事项继承支出成员，负收入事项也从支出成员推导。成员有效预算唯一则自动继承，跨预算则标记待确认；原始流水标签不被重写。正净收入分配继续使用 `budget_income_allocations`，事项承担字段不创造资金。

统一入口位于事项编辑区域：选择“消费 / 净亏损承担预算”，预览当前净额及预算处理；正净收入提供“分配净收入”按钮，直接打开既有按金额拆分弹窗，保存后刷新事项。列表也提供事项预算入口。事项详情展示实际收入分配，成员的回款及分出明确显示随事项处理，避免把旧标签误认为真实预算分配。

预算执行、存储剩余及特殊消费、预算筛选、Excel 复用同一预算消费投影。负净收入保留原事项身份与日期，只在预算消费投影中作为净亏损扣款，预算查询仍显示原方向的负净收入；已分配收入变为负数时保留原分配并明确超配，预算结余标为未完整，已知净亏损仍参与计算。缺汇率或跨预算的潜在亏损不得默默漏掉后显示完整。

首次升级添加承担字段前备份 `finance-pre-offset-budget-*.db`，原字段留空自动继承；旧事项及真实流水金额不变。承担预算改动沿用事项版本、备份与审计，旧客户端省略字段时保留原值。当前漏算的工资事项在核对原记录后明确选择对应的工资预算，保留成员和金额。验收覆盖正/负/零净额、净额跨零变化、跨币种、缺汇率、跨预算、结转、存储与导出一致性及旧接口兼容。

回归入口：`tests/test_offset_budgets.py` 使用隔离账本验证上述计算及一次性备份，`tests/offset_budgets_browser.cjs` 使用临时服务验证桌面收入拆分、承担预算、失败保留草稿及净额跨零后的旧分配修复；均核对原始流水和账户余额。

收入事项也可表达用户希望按净额统计的项目或工资收入：例如将聘用成本从收入中扣除。是否组装取决于希望统计的事项含义，不由“先收入还是先付款”决定，也不局限于纯粹代收代付。被组装的支出已反映在净收入中，不能在同一套净收支合计里再算一次消费。

支出事项如 AA 垫付只贡献付款减收回后的净消费，不产生额外收入。预算可展示到账、分出及净额组成，但不重复计入；当前收入分配与预算额度规则见[预算设计](budget-and-fund-allocation-design.md#2026-10-20-由收入分配生成预算额度已实现)。

AA 回款的原始类型为收入，分类使用“报销/返还”，录入时选择“暂不分配预算”。若误把回款分配成新增预算收入，应先从“查看 / 修改收入预算分配”移除全部分配，再与原付款组织支出冲销；不同聚餐按各自实际付款、回款分别关联。跨币种保持原始账户及金额，用原日期保存汇率换算。回款通过事项减少主支出所属预算的消费，不再分配一次预算收入。批量纠正时，取消分配、更新月计划缓存/版本与建立事项在同一事务完成，保留原流水及备注，先备份并分别写预算与事项审计；验证账户余额、真实流水不变，其他预算分配不受影响。

银行或信用卡“回赠”作为独立收入分类记录。消费后来退款且银行同时撤销回赠时，应建立两个事项：购买与退款组成支出冲销，回赠与撤销组成收入冲销。这样交通、购物等净消费仍归原支出分类，净回赠仍归“回赠”；不能把四笔合并，否则事项只能继承一个方向和一个分类，会丢失两种业务含义。跨币种时每笔仍保留实际入账币种并按各自日期换算。

## 2. 三种查看粒度

| 粒度 | 记录内容 | 用途 |
| --- | --- | --- |
| 原始流水 | 一次实际收付款，保留原日期、账户、币种、金额、分类、对象、备注 | 对账、查看资金路径、编辑真实记录 |
| 冲销事项 | 多笔关联流水，指定方向并自动推导日期和分类 | 查看一件事当前的净支出或净收入 |
| 日期 / 月份 / 分类汇总 | 未关联流水与冲销事项形成的统计结果 | 月度收支、日历、直方图和分类分析 |

一个事项在冲销后列表中占一行，并显示“关联 N 笔”。展开仅展示原始明细，不再次计入汇总。普通未关联流水仍占一行。

使用 `entry_count` 表示统计记录数，`transaction_count` 表示关联的原始流水数；两个值不得混用。一项关联五笔流水，应显示“1 个事项，5 笔原始流水”。

## 3. 方向、金额和不变量

### 3.1 计算公式

对于同一个目标计价币种 B，先逐笔换算，再按方向求和：

```text
支出事项的支出金额 E(B) = Σ支出流水金额(B) − Σ收入流水金额(B)
收入事项的收入金额 I(B) = Σ收入流水金额(B) − Σ支出流水金额(B)
```

支出事项只占用“支出”统计字段，收入字段为零；收入事项反之。净额可以为负，不因符号改变事项方向，不取绝对值，不截断为零。

| 场景（同币种） | 原始支出 | 原始收入 | 冲销后收入 | 冲销后支出 |
| --- | ---: | ---: | ---: | ---: |
| 聚餐垫付 | 600 | 200 + 150 | 0 | 250 |
| 两次代收、三次分发 | 1000 + 1500 + 500 | 3000 + 2000 | 2000 | 0 |
| 完全收回 | 300 | 300 | 0 | 0 |
| 收回超过垫付 | 100 | 120 | 0 | -20 |
| 分发超过代收 | 120 | 100 | -20 | 0 |

尚未把所有实际流水加入事项时，也按当前成员计算。页面称“按已关联流水计算”，不声称这是最终成本或最终收入。

### 3.2 完整范围内的净额守恒

在涵盖全部相关原始日期与事项统计日期、采用相同汇率快照和精度规则、全部可换算的范围内：

```text
冲销后收入合计 − 冲销后支出合计
= 原始收入合计 − 原始支出合计
```

收入总额、支出总额和笔数本来就会变化；按日、月、分类、涉及账户等局部筛选的结果也可能变化。上述等式不保证任意月份或任意筛选切片分别相等。

组装、修改关联和解散事项不改变任何账户的余额、逐笔余额、资产、负债、净资产或原始资金流。不得把事项净额写回 `transactions` 或 `account_balances`。

这里的净收支守恒不等同于净资产变动：后者还涉及投资估值、汇率重估、调整等既有因素。

## 4. 自动日期与分类（用户修订）

### 2026-11-18：混合支出分类与回款分摊（本轮实现）

原实现把事项全部净额归最早主流水，金额合计正确，但不同消费分类被合并，且分类筛选只能命中最早分类。本轮仅扩展支出事项；收入事项与收入预算分配保留现有规则。以下规则优先于本文历史的“单事项单分类 / 暂不分摊”描述。

- 支出事项增加 `category_allocation_mode`：`anchor` 沿用最早主流水；`proportional` 保留所有支出原分类。新建支出默认后者，历史事项迁移后保留前者，可在事项中主动切换并预览。收入事项使用 `anchor`。缓存 `category_id` 仍为最早主流水，不改真实流水分类。
- 比例模式中，共享优惠 / 返还按各支出换算后的原金额占比分摊，不按笔数、不按已扣退款后的余额。每笔回款可改为只冲减指定的一笔支出；支持多个回款分别指定。未指定的部分继续按全部原支出比例分配。指定金额可超过对应消费，允许产生负分类净额，不静默截断。
- 回款目标只引用同一事项内的支出成员，保存时校验唯一性、方向和成员关系；旧客户端省略字段保留已有设置。移除成员时必须同时解除相关指定；修改原始类型使指定失效时拒绝并提示先调整事项。修改金额、分类、汇率后实时重算。
- 每笔按原日期汇率换算，再按目标计价币种计算比例；内部使用 Decimal 并保留精度，末项承接计算残差。展示分类明细与分类分布时以最大余数法分配分币尾差，分别保证当前事项 / 当前汇总的可见分类合计等于对应净额。不同独立筛选的显示舍入仍可能有最小货币单位差异，原始净额及全量收支合计不改变。缺少任一所需汇率时该事项在该计价下整体不完整，不能伪造分类精确值。
- 事项列表仍占一行，混合分类显示“多分类”，展开显示原金额、冲减及各分类净额。分类筛选只汇总所选分类份额，但保留全部成员用于追溯，并同时显示完整事项净额。多选分类是并集，事项、账户分布、日历与笔数不重复；分类分布按份额累计。
- 第三页查询、分析、概况 Excel 的分类月预算与新增“冲销分类分摊”表使用同一分摊函数。第六页预算承担、净支出、存储扣款与结转仍使用完整事项一次，不因分类拆分而拆预算。原始收付、余额、真实分类和常用排序不变。
- 新表保存回款到支出的映射；升级前备份 `finance-pre-offset-categories-*.db`，历史事项不自动改统计方式。模式和映射与事项成员同事务、同版本、同备份及审计保存。测试使用隔离账本，覆盖比例 / 指定 / 负数 / 零净额、跨币种与缺汇率、筛选和图表笔数、导出、历史迁移及余额预算守恒。

验证：`tests/test_offset_categories.py` 覆盖上述计算、旧接口、导出与迁移；`tests/offset_categories_browser.cjs` 验证电脑浏览器的切换、预览、指定回款、冲突保留草稿、移除成员和第三页份额查询。全套 140 项测试通过；实际修正指定事项前使用账本副本核对原始流水、余额、预算与其他事项不变，再通过既有备份 / 审计接口保存。

事项表单只填写名称、方向、备注并选择原始流水，不输入统计日期、分类或起点。

- 统计日期是全部成员的最早 `transaction_date`，包括主方向与冲抵方向；追加更早记录、移除最早记录、修改原始日期后立即重新计算。
- 分类默认自动继承最早主方向流水的原始分类；同日按流水 ID 排序。例如支出事项继承最早支出分类，收入事项继承最早收入分类。不同主分类暂统一归最早主流水，页面同时显示各成员原分类，不额外预测或分摊。
- `anchor_transaction_id` 是自动推导的最早主流水 ID，不再由用户选择。
- 数据库中已有的日期、分类和起点字段保留兼容，但读取结果以实际成员推导为准；事项写入及关联原始流水更新时同步缓存，原流水不被改写。
- 允许引用历史已停用分类，因为分类来自已有原始流水；不再要求用户另选启用分类。
- 收入 / 支出方向仍由用户指定，至少需要一笔该方向的主流水。移除原起点后，自动采用剩余最早主流水；只剩冲抵流水时应改方向或解散。

跨月示例：9 月 30 日支付 100，10 月 2 日收回 80，事项自动归 9 月 30 日，净支出 20。若后来加入 9 月 20 日的关联记录，事项自动移到 9 月 20 日。汇率仍按各笔原始日期换算。

## 5. 跨币种与精度

### 2026-11-18：默认按原币统计与流水币种筛选（本轮实现）

原概况切换口径时，原始收付的 CNY 仅包含人民币，而冲销后的 CNY 包含全部币种折算，两者同名但范围不同。本轮将概况、冲销查询和事项的主要金额统一为“按原币分别统计”，原 CNY / HKD 折算值保留为明确命名的辅助信息；预算执行仍按预算币种换算，资产本币总统计不变。

- 同一事项按每个原币分别计算主方向减冲抵方向，绝不跨币种相减。例如支出 100 HKD、收回 80 CNY，原币净支出分别为 100 HKD、-80 CNY；完整事项折算净额另行展示。允许负原币收入 / 支出，不能将它们归零或误作另一币种。原币不依赖汇率；同一成员集合、同一日期范围下，各币种的收入减支出在原始 / 冲销两口径守恒。
- 新增 `currency_code` 查询参数和第三页“流水币种”单选，空值表示全部币种分别显示。包含停用币种以便查询历史。原始流水只要任一资金腿币种匹配即命中；金额汇总只计算匹配资金腿，换汇两端仍完整展示。账户筛选和币种筛选必须同时满足所统计资金腿，不从另一端引入金额。
- 冲销查询按原始成员币种命中事项，保留全部成员供追溯，只累计所选币种的原币净额；不把事项其他币种折算后塞入该值。币种过滤与分类份额、预算份额组合，不重复事项。事项统计日期仍为最早成员日，所以跨月事项与原始日期的月汇总可能不同，页面明确提示。
- 混合分类的原币分摊保持原支出分类：当前币种的原消费归自身类别，当前币种回款按指定对象或原支出权重扣减。跨币种原支出权重必要时依赖汇率；无法确定分类份额则分类筛选 / 图表标记未完整，但未筛选分类的原币合计仍可直接计算。收入预算筛选继续只计已分配份额，按来源币种占用比例投影至原币，失效分配不作为已核实收入。
- 查询选定币种后，日历、直方图、分类 / 账户分布直接按该原币统计，界面单位随币种变化，不再硬编码 HKD。未选择币种的多币种图表保留现有 HKD 折算并明确标注，主要汇总仍分原币显示。Excel 月度总览跟随原币口径，完整折算值移到明确命名的附表，原始流水和分类换算表保持可追溯。
- 本轮只增加只读投影与筛选，无数据库金额或归属迁移。验证同币种与跨币种事项、跨币种返还、换汇单边 / 账户组合、停用币种、分类与预算组合、分页完整汇总、原币无需汇率、动态图表单位、Excel 及原始记账 / 余额 / 预算兼容。

验证记录：`tests/test_native_currency.py` 覆盖原币守恒、换汇资金腿、原币分类 / 预算份额、停用币种、缺汇率、分页与导出；`tests/native_currency_browser.cjs` 验证概况切换、第三页币种选择和动态图表单位、无匹配及重置；混合分类桌面回归继续通过。全套 150 项自动测试通过，正式账本以只读方式核对当前月份及全历史逐币种结余守恒，未执行任何账本写入。

### 5.1 原币明细与统一计价

原币金额始终保留并按币种分行。混合 HKD、CNY 的事项没有一个可直接相加的“原币总额”，不得把数字直接相减后挂上起点币种。

事项提供：

1. 原始支出、原始收入的各币种合计，用于核对。
2. 依事项方向计算的各币种有符号分项，用于追溯，不将它们跨币种相加。
3. 分别独立计算的 CNY、HKD 净额，供统一计价统计使用。

同币种事项可以额外展示该币种的精确净额；统一计价仍逐笔按原日期换算，不能先合成一个原币净额再按事项日换算。

### 5.2 汇率日期

沿用当前系统已保存的 `daily_cny_exchange_rates`：优先原始流水当天快照，没有当天记录时取最近快照；距离相同取较早日期。查询过程不联网、不补写汇率。

统计日期只决定结果归属；每笔换算均使用该笔自己的原始日期。CNY、HKD 两种结果分别由原始成员计算，不能把一个净额按某一天汇率二次换成另一个净额。

例如支付 600 HKD，随后收回 600 CNY，假设收回日 `1 CNY = 1.1 HKD`，则 HKD 净支出为 `600 − 660 = -60 HKD`。

修改系统历史汇率后，受影响的事项与原始统计一同重算；不在事项表存储过期的换算净额。

### 5.3 缺失汇率与不支持币种

采用按目标币种判断的完整性规则：一个事项的任一成员不能换算到目标币种，则该事项在该目标币种下的净额为 `null`，不能展示已成功换算部分作为完整净额。

- 原始明细、成员数量和原币分项照常显示。
- 汇总展示“可计算部分合计”及未纳入的事项 / 普通流水数量、币种和原因，不显示为完整总计。
- 不把被排除事项的成员重新当成未关联流水计入，避免重复或不对称抵扣。
- CNY、HKD 的覆盖分别判断；某个币种可计算，不代表另一个也可计算。
- 查询结果包含但无法换算的记录，在日历、分布、导出中保留缺失提示，不能当零金额。

EUR 等同币种事项可计算原币净额，但没有支持的汇率时不进入 CNY、HKD 合计。完整净额守恒只比较两种口径均完整覆盖的相同成员集合。

### 5.4 金额精度

原始金额继续按最小货币单位存整数；换算使用 `Decimal`，不使用浮点数。

共享换算函数对每笔保留未舍入计算值，事项合计和最终汇总完成后再按目标币种小数位统一四舍五入。原始口径与冲销口径使用同一规则，不把界面已格式化金额拿来二次累计。分别显示的事项净额可能因显示舍入与总计出现最小货币单位差异，导出和界面须使用相同计算来源。

## 6. 两套统计数据及筛选顺序

### 6.1 原始收付 `raw`

使用现有真实流水、原始类型、日期、分类和账户范围。转账、换汇、投资损益和调整等沿用既有规则。

新增事项关联标记和跳转入口，不改变原始查询结果、查询资金流汇总和账户余额算法。

### 6.2 冲销后收支 `offset`

个人收支结果集合由以下两部分构成：

```text
全部未关联事项的 income / expense 流水
UNION ALL
每个事项的一条净额统计记录
```

事项的所有成员先从普通流水集合中排除，再由事项结果替代。转账、换汇、投资估值损益和手工调整不进入个人收支结果；要分析这些类型，使用原始流水口径。

处理顺序：

1. 获取事项及完整成员，包括位于查询日期范围外的成员。
2. 逐笔换算，计算每个事项的完整净额和覆盖信息。
3. 与未关联收入 / 支出组成统一结果，应用以下筛选语义。
4. 对完整命中集合计算数量、金额汇总和图表。
5. 最后分页；分页不得影响汇总。

实现时可以先按事项自身字段缩小候选事项，但不得把成员按日期、类别、账户或关键词过滤后再计算净额。

| 筛选项 | 普通流水 | 冲销事项 |
| --- | --- | --- |
| 日期 | 原始日期 | 事项统计日期 |
| 收入 / 支出 | 原始类型 | 事项方向；负数不改变方向 |
| 分类 | 原始分类 | 事项分类 |
| 关键词 | 既有对象 / 备注等查询字段 | 事项标题、备注、统计分类，或任一成员的原始对象 / 备注 / 分类命中，返回完整事项 |
| 涉及账户 | 流水的收付款账户 | 任一成员涉及该账户即命中，返回完整事项 |
| 仅待核实 | 原始标记 | 任一成员有待核实标记即命中，返回完整事项 |

冲销模式下，账户筛选名称明确为“涉及账户”，不承诺结果等于该账户的净流入或余额变动。对跨账户事项不把其他账户的成员丢掉；单账户资金核对仍在账户明细完成。不同涉及账户筛选结果可能命中同一事项，不能相加。

两种口径共用日期、收入 / 支出、类别、关键词等兼容条件。切换到冲销口径时遇到转账、调整或“仅手工调整”等不适用条件，显示明确说明并要求改选或清除，不能静默忽略。

### 6.3 账户分布

冲销口径的账户分布按每条统计记录唯一归桶：普通流水及仅涉及一个账户的事项归该账户；涉及多个账户的事项统一归“多账户事项”，可展开查看。

不把一个事项全额重复分到每个账户，也不假定净额全部发生在第一笔的账户。该分布表示统计记录的涉及账户情况，原始账户资金流分布仍使用原始口径。

## 7. 数据模型

新增两张表；不修改 `transactions` 的金额字段或 `account_balances` 视图。

### 7.1 transaction_offset_groups

| 字段 | 类型与规则 |
| --- | --- |
| `id` | INTEGER 主键 |
| `title` | TEXT 必填，建议最多 120 字 |
| `kind` | TEXT，`expense` 或 `income` |
| `anchor_transaction_id` | 自动取最早主方向流水（同日按编号），`ON DELETE RESTRICT` |
| `statistics_date` | TEXT，自动推导的最早成员日期缓存，不接受用户指定 |
| `category_id` | 最早主方向流水的原始分类缓存，`ON DELETE RESTRICT` |
| `note` | TEXT 可空，建议最多 500 字 |
| `version` | INTEGER，从 1 开始，用于避免陈旧编辑覆盖 |
| `created_at`、`updated_at` | 时间戳 |

建议索引：`statistics_date, id`；`kind, category_id, statistics_date`。

不保存结清状态、预计金额、本人份额、最终净额、汇率副本或计算币种。净额由当前成员和当前保存的汇率实时计算。

### 7.2 transaction_offset_members

| 字段 | 类型与规则 |
| --- | --- |
| `transaction_id` | 主键，引用原始流水，`ON DELETE RESTRICT`；保证一笔只能属于一个事项 |
| `group_id` | 引用事项，`ON DELETE CASCADE` |
| `created_at` | 加入时间 |

为 `group_id` 建索引。成员的金额、日期、账户、类型和分类均从原始流水读取，不复制为第二份账本。

主方向 / 冲抵方向由原始类型与事项 `kind` 推导，不单独存可失配的角色字段。

### 7.3 跨表校验

由统一服务函数在写事务内检查：

- 所有成员都存在，且仅允许 `income` / `expense`。
- 至少保留一笔主方向流水；允许冲抵一侧暂时为空，不引入结清概念。
- 起点必须在该事项成员内，且类型与事项方向一致。
- 成员 ID 不重复，未被其他事项占用。
- 统计分类继承最早主流水，包括历史停用分类，不要求重新选择当前启用分类。
- 不按日期先后限制成员加入，支持补记、跨月、先收到后补付款等情况。

外键、唯一键和 `CHECK` 负责可表达的约束；跨表规则通过服务事务校验。直接修改 SQLite 时也须遵循这些规则。

## 8. 创建、更新、解散与原始记录编辑

事项写操作沿用数据库备份与审计机制。流程为：基础参数校验，创建备份，开启写事务，重新检查成员占用和版本，保存事项及完整成员集合，记录审计，一次性提交。失败时数据库回滚，不留下半个事项。

给 `change_audit_logs.entity_type` 增加 `offset_group`，操作复用 `create` / `update` / `delete`。审计快照包含事项字段、成员 ID 及当时各成员的金额、日期、类型、账户等信息；解散采用 `delete`。追加、移除、切换方向均视为事项更新，并重新推导归属。

### 8.1 事项修改

- 保存提交完整成员列表，服务端先比较 `version`，成功后递增。
- 修改方向后自动从该方向的成员重新计算分类和起点，通过整体校验再提交。
- 移除原起点后自动选择剩余最早主流水；移除最后一笔主方向流水时应解散事项或调整方向，不能保留无效结构。
- 解散仅删除事项和成员关联，保留原始流水，立即恢复原始记录在冲销口径中的独立统计。
- 提交冲突返回 `409`，保留用户当前编辑内容，提示刷新后重新核对。

### 8.2 原始流水修改和删除

- 金额、日期、账户、分类等原始修改会实时改变事项计算结果，自动重算最早日期和主流水分类。
- 成员原始记录更新时，在同一事务中更新关联事项版本，保存关联事项修改前后审计快照，避免另一页面用旧信息覆盖。
- 原始类型变化仍须满足事项规则；改成转账 / 换汇 / 调整或导致没有主方向记录时，先移除关联或编辑事项；仍有主方向记录时自动重选起点。
- 第一版禁止直接删除仍有关联的流水，返回 `409` 并提供事项链接。先从事项移除或解散，再走现有流水删除流程，避免隐式删掉关联、起点或整项统计。
- 从事项移除仅改变统计关联；从流水页删除才删除实际记录，两种操作使用明确名称。

保存前的预览必须读取当前原始记录和汇率，正式保存时重新校验并计算，不能信任前端传入的净额。汇率变更不改变成员关系或事项版本，但结果返回所用快照日期 / 更新时间，便于核对。

## 9. 第五页交互

路径建议为 `/offsets`，导航标题“冲销与代收代付”，所有现有页面补上入口。

### 9.1 事项列表

支持统计日期、方向、分类、涉及账户、关键词筛选。每行展示：统计日期、标题、方向 / 分类、主方向与冲抵方向笔数、原币分项、CNY / HKD 净额、编辑和展开入口。

零额事项照常显示；负额保留负号；汇率缺失显示“无法完整换算”。展开显示全部成员，并标出不在当前查询日期内的原始记录。

### 9.2 创建 / 编辑布局

```text
事项名称    支出冲销 / 收入冲销
备注
自动归属提示：最早成员日期 / 最早主流水原分类

上方：主流水
  支出事项：多笔支出；收入事项：多笔收入
  每笔显示日期、账户、币种、金额、分类、对象、备注
  最早主流水标记 / 移除关联
  [选择已有流水]

下方：冲抵流水
  支出事项：多笔收入；收入事项：多笔支出
  每笔保留同样的原始信息，可移除关联
  [选择已有流水]

合计预览：原币分项、CNY 净额、HKD 净额、换算覆盖
统计归属：日期、分类；按已关联流水计算
[保存事项]    [取消]
```

选择已有流水的弹窗提供日期、账户、分类、对象 / 备注查询及分页多选。候选项按上 / 下区域限制收入或支出方向。已属于其他事项的记录不可重复选择，同时提供查看所属事项入口；编辑当前事项时保留已经选中的成员，候选日期变化不丢失选择。

本页只选择已有流水，不自动补造未来记录。用户先在记账页录入新事务，再返回追加；可以提供返回记账页的便捷入口。

编辑页的移除按钮只改当前编辑集合，点击保存才一次性写入。解散对话框明确展示事项名称和成员笔数，说明原始流水仍然保留。

## 10. 现有页面、统计与导出

### 10.1 概况页

收入 / 支出 / 结余区域提供“原始收付 / 冲销后收支”切换，初次默认原始口径以保持现有行为；各页面分别记住用户明确选择，后续进入沿用。各结果区明确显示当前口径。

- 原始模式继续展示现有按原币种收支。
- 冲销模式重点展示 CNY、HKD 两种计价的收入、支出、结余和换算覆盖；原币分项仅用于追溯，不把混合币种事项当成一种原币净额。
- 账户余额、可用现金、总资产 / 负债 / 净资产、内部资金流动仍是原始账本结果，明确标注“账户实际余额 / 原始资金流”，不受此切换影响。
- 最近流水保持原始逐笔展示，增加事项标记；不因收支卡片切换而隐藏实际收付款。

### 10.2 账户与流水页

账户明细始终展示原始资金流和逐笔余额，成员显示事项链接。

跨账户查询提供原始收付、冲销后收支及仅冲销事项三种选项。原始模式保留现有接口语义；冲销模式中，未关联的普通收入 / 支出只显示一行原始金额摘要和编辑入口，不重复展示 CNY / HKD 净额、换算覆盖、原币收支分项或“展开 1 笔原始流水”。真正的冲销事项才显示统一计价净额、换算覆盖并允许展开全部成员。仅冲销事项使用相同统计逻辑并过滤未关联流水。

原始模式不改变现有单账户资金腿汇总；冲销模式“涉及账户”的含义按第 6 节执行。

### 10.3 日历、直方图与分布

冲销模式仍要求完整日期范围、不超过 12 个自然月、只选择收入或支出一种方向；仍按每日合计作为统计样本。

- 事项按统计日期放入日历，未关联流水按原日期放入。
- 负金额参与日均、中位数、极值、方差等计算，最高支出不使用绝对值替换。
- 日历可点击零净额事项所在日期；“有记录天数”按记录存在判断，不能用金额非零判断。与没有任何记录的日期区分。
- 直方图支持负区间及零值，继续使用整数 HKD 的 `1 / 2 / 5 × 10^n` 分箱，左闭右开，最后一箱包含右端点；全零数据也有有效展示。
- 分类与涉及账户分布使用有符号横条图。金额占比在全部分类净额非负且总额大于零时展示；存在负分类金额、净额总计为零或换算不完整时，不展示容易误解的百分比，保留金额及原因。
- 换算不完整的事项不作为零值样本；显示覆盖情况。点击某日打开冲销后结果，再展开即可查看其他日期的原始成员。
- 收入与支出不混为一个分布样本；原始转账 / 调整分析功能保留。

### 10.4 预算与 Excel

导出传入与页面一致的 `basis` 参数，在月度总览、收支汇总和预算执行表中注明统计口径。

- 原始“交易流水”“账户余额”“内部资金流动”等表始终保留真实记录。
- 增加“冲销事项”“冲销关联明细”“个人收支”表。个人收支按选定期间的统计日期筛选；涉及事项的关联明细须完整导出，即使成员日期不在该期间。
- 冲销事项表保留原币分项、两种计价净额、统计日期、分类和换算覆盖；不把事项附加写进原始流水表参与余额。
- 冲销模式预算执行：按预算月份、分类筛选完整统计结果，将每条结果逐成员换算到预算币种后求和。CNY / HKD 预算可汇入支持换算的各币种消费，表头注明“折算至预算币种”；与原始模式仅统计同币种支出的既有规则明确区分。
- EUR / JPY 等暂无统一换算支持的预算：只有与预算同币种的完整记录能直接计算；其他符合月份、分类的记录属于覆盖缺失，显示可计算部分及原因，不能显示完整预算执行率。
- 负支出可减少预算实际支出，不自动归零。预算执行与图表汇总复用相同统计结果；不得一个扣冲销、另一个仍计原额。
- 常用账户 / 分类排序继续基于真实原始流水的每日快照，组装事项不改变使用频率。

## 11. API 草案与返回语义

### 11.1 事项维护

| 方法 | 路径 | 含义 |
| --- | --- | --- |
| GET | `/api/offset-candidates` | 按原始日期、账户、方向、分类、关键词分页选择已有流水，返回占用事项信息 |
| GET | `/api/offset-groups` | 事项列表、分页、过滤及覆盖全部命中项的汇总 |

| POST | `/api/offset-groups/preview` | 校验尚未保存的编辑内容并计算预览，只读，无备份 / 联网 |
| POST | `/api/offset-groups` | 创建事项及完整成员集合 |
| PUT | `/api/offset-groups/{id}` | 携带 `expected_version` 替换元数据和成员集合 |
| DELETE | `/api/offset-groups/{id}` | 携带 `expected_version` 解散，仅删除关联对象 |

写入字段：`title`、`kind`、`note`、`transaction_ids`、`budget_system_id`、`category_allocation_mode`、`category_targets`。后者为 `{refund_transaction_id, expense_transaction_id}` 数组，空数组清空，省略保留旧指定。新建支出默认 `proportional`，更新省略模式保留原值，收入只支持 `anchor`。日期、分类缓存、起点由服务端从成员推导；兼容旧客户端传入的三个字段，但忽略其值。更新额外提供 `expected_version`；服务端不接收客户端计算的净额作为账本值。返回 `category_ids`、多分类名称、`category_breakdown`；筛选份额标记 `category_basis/selected_category_ids` 并提供 `whole_valuations`。

错误：参数 / 成员类型不合法为 `422`，对象不存在为 `404`，成员占用、版本冲突、删除关联流水等业务冲突为 `409`。错误内容给出事项 ID 和可操作原因。

### 11.2 查询接口

原始 `GET /api/transactions/search` 保持原语义，增加成员的 `offset_group_id`、标题、方向；选择器使用独立的 `/api/offset-candidates`，展示被其他事项占用的记录及所属事项链接。

新增 `GET /api/personal-cashflow/search` 和 `GET /api/personal-cashflow/analysis` 专门返回冲销后结果，避免把原始流水响应改造成含负数和混合币种的伪流水。两者共享筛选、换算和结果生成逻辑。

冲销后记录包括：

- `entry_type`: `transaction` 或 `offset_group`。
- `entry_id`、`statistics_date`、`kind`、`category`、标题 / 备注。
- `transaction_count`、`member_transaction_ids`、`involved_accounts`、是否含待核实成员。
- 原币分项，以及 CNY / HKD 的 `amount`、`available`、覆盖和缺失信息。
- 普通流水的记录数为 1；事项成员不在顶层重复出现。前端键使用类型与 ID 的组合，避免两类 ID 相撞。

筛选支持日期、一个或多个收入 / 支出方向、多个分类、`involved_account_id`、关键词、待核实、分页及 `entry_type`（只看冲销事项或只看未关联流水）。分析限制单一方向；搜索汇总可以分别汇总两种方向。

`GET /api/dashboard`、`GET /api/export.xlsx` 增加 `basis=raw|offset`，默认 `raw`。保留既有余额与原始资金流返回结构；新增个人收支区域或明确结构字段，不把混合币种净额塞入旧的按原币种字段。

静态路径 `/preview` 注册在动态事项 ID 路径前，避免被动态路由误匹配。

## 12. 实施划分与迁移

现有 `app/main.py` 已集中较多业务。本功能新增独立的事项服务和个人收支统计模块（建议 `app/offsets.py`、`app/personal_cashflow.py`）；公共金额与汇率工具抽取为无路由依赖模块。路由调用服务，查询、图表和导出使用同一个统计入口，避免每处复制冲销算法。

建议实施顺序：

1. 增加两张表、索引和审计实体迁移，旧数据库无需重写流水；迁移前备份。
2. 实现事项创建、预览、更新、解散和原始流水关联保护。
3. 实现统一个人收支结果、逐笔换算、筛选与完整性标记，验证净额守恒。
4. 实现第五页和所有页面导航，原始明细补关联入口。
5. 接入概况、查询、日历、直方图、预算和 Excel，明确原始 / 冲销口径。
6. 更新使用说明、数据库手册、各专题设计与真实实现一致的部分。
7. 完成隔离回归和页面检查，结束验证服务，由用户启动查看。

迁移必须可重复运行，保留当前审计实体（包括投资估值、汇率）和已有记录。现有 `migrate_change_audit_logs` 对允许实体的检查与重建结构需同步更新，防止后续初始化重建为旧约束。既有账户活动快照迁移保持兼容。

此设计不要求修改或提交当前工作区已有的账户优先级、图标等未提交实现；开发时在现有改动基础上增量进行。

## 13. 验收与测试计划

测试使用临时数据库和固定汇率，不接触 `data/finance.db`，不依赖实时外部 API。

| 场景 | 核心断言 |
| --- | --- |
| 付 600、收 200 和 150 | 原始结果保留三笔；冲销后一个支出事项 250，收入为零 |
| 收 3000 和 2000、付 1000 / 1500 / 500 | 一项收入 2000，关联五笔，不要求成对匹配 |
| 零额和负额 | 完全抵消事项仍可查；付 100 收 120 为支出 -20；反向场景为收入 -20 |
| 一侧暂为空 | 一笔主流水可建事项，以实际成员计算，追加后立即更新，无结清字段 |
| 余额与完整净额 | 建立 / 修改关联 / 解散前后，所有账户余额与原始资金流逐项一致；全覆盖统一计价净额守恒 |
| 跨月追加 | 9 月事项关联 10 月回款，9 月净额更新；10 月冲销后不重复计收入；原始月度结果不变 |
| 自动归属 | 新增更早记录、移除最早记录、修改成员原日期会自动更新日期；分类来自最早主方向原始流水 |
| 跨币种不同日期 | 按各笔原日期汇率转换，CNY / HKD 独立求和；禁止使用事项日单一汇率代替 |
| 同币种、不同日期汇率 | 原币净额为零时，目标币种净额仍可能非零，按实际逐笔换算值显示 |
| 缺汇率 | 缺一笔则该事项目标净额不可用；不把其余成员组成部分净额，不把成员退回普通流水重复计入 |
| 日期 / 分类 / 账户过滤 | 过滤事项结果而非裁剪成员；关键词命中一个成员仍计完整事项；涉及账户结果不冒充账户资金流 |
| 分页 | 明细分页不改变汇总、图表及全部命中记录数 |
| 关联唯一性与并发 | 同一原始流水不可属于两项；版本过期或成员被占用返回 409，写入完整回滚 |
| 原始修改 / 删除 | 修改金额导致重算并更新版本；删除有关联流水被拒绝；移除关联后才允许正常删除 |
| 无效结构 | 非收入 / 支出成员、移除最后主流水均被拒绝；起点与分类自动按方向推导 |
| 解散 | 仅删除关联，原始流水、标记保留，冲销后统计恢复为逐笔 |
| 负数及零值图表 | 负桶边界、跨零、全零、日均、中位数、分布占比规则正确；缺失不算零 |
| 预算及 Excel | 页面和导出用同一口径与换算；跨月成员完整列出；余额表仍与原始账户一致 |
| 迁移与审计 | 旧库迁移、重复初始化成功；保留原审计实体；每次事项写入均有备份与前后快照 |

验证还应覆盖没有任何事项时的兼容性：原始页面结果不变；冲销口径的个人收入 / 支出等于同样日期、分类和换算规则下的原始收入 / 支出，其他类型不误纳入。

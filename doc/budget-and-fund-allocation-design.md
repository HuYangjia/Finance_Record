# 第六页：多预算计划与自定义栏目设计

设计日期：2026-10-01。状态：首版已实现；预算计划与实际流水分开保存。正式账本在下次启动时自动备份并升级。

2026-10-01 追加：未单独指定预算的实际支出自动按日常预算查询，包括历史消费；具体规则见 [预算归属设计](budget-attribution-and-settings-design.md)。这只改变第三页的统计归类，不扣减本页计划。界面统一层级、间距和配色，保留逐笔预算、总表、复制、历史及导出功能。

## 公共存储目录（已实现）

用户确认“一套公共存储目录，各预算独立分配”。设置及预算录入已使用公共目录，以下规则替代旧稿中每预算独立维护存储方式的设计：

- 存储方式由设置页统一管理，活期、定期、ETF、股票及子层级对全部预算可选；新增一次即可共用，无须复制栏目或逐预算配置启用清单。
- 共用的是栏目身份和层级，金额仍保存在各预算、各月份的分配明细中。总表按公共栏目归集，同时保留每个预算的来源和金额。
- 存储栏目不绑定币种，金额继承所属预算的统一币种；不同币种合计继续分别展示。
- 改名对所有预算生效；停用后禁止新选择，已有明细仍保留，历史快照继续展示原名称和层级。
- 实现前备份。旧栏目需检查完整路径及含义后映射到公共目录，不能只因末级同名就误合并；保留原金额、分配归属和历史，不改真实流水。现有每预算栏目复制入口随新结构调整。

## 交叉总表：存储剩余与对齐（2026-10-02，已实现）

问题分析：旧交叉总表只汇总各存储方式的累计安排，未扣消费；“预算执行与连续结转”已按预算系统计算消费后的结余。此前真实消费只标记预算系统，缺少存储扣减来源，因此无法推断活期、定期、ETF 各自剩余，也不能把总消费从每个格子重复扣一遍。

现在新增独立的“截至所选月剩余”视图，保留原计划累计用于追溯。预算总余额沿用现有完整冲销与连续结转；存储余额采用 `期初存储余额＋新增分配＋调入－调出－归属该存储的净消费`。期初进入待分配；没有默认扣款且没有单独归属的消费，先使用待分配的正余额，再使用启用的顶级“活期”正余额，仍不足的部分才单列待归属消费。剩余视图不因累计区间筛选而丢弃此前结余。此处表示预算额度，ETF 等投资市值仍由投资页面计算。

用户确认并已实现：每个预算可以指定默认消费存储（例如活期），日常自动归入，少量例外可改归属；没有显式规则时按“待分配 → 活期 → 待归属消费”的顺序自动吸收。自动吸收只使用现有正余额，不把待分配或活期扣成负数，也不自动动用定期、ETF、股票等其他存储；负净消费没有明确原存储时回补待分配。不足时显示缺口并手动进行同预算、同币种的存储调拨，不自动卖出投资或生成真实转账。调拨仅改变两列余额，不改变预算总额、不重新占用收入来源；不能通过调小历史新增预算来表示已经花掉的钱。使用净支出事项作为扣减单位，AA 回款回到原消费归属，收入事项的分出不重复算消费。

对齐修复：中间列表头原本左对齐，金额按钮居中且带左右内边距，合计纯文本右对齐；所有 `th` 都横向吸附又使滚动时中间表头重叠。现统一表头与数字右边缘、首列名称左对齐，仅首列横向吸附。样式限于 `#budget-matrix`，保留其他表格和手机样式；计划视图点击金额仍查看计划明细，剩余视图点击金额进入存储维护。

验收结果：隔离账本上的月度、累计、一级存储汇总、交换行列四种显示均通过数字右边缘检查；横向滚动仅固定名称列，点击金额仍可打开明细，合计金额保持一致。桌面截图已核对，JavaScript 语法检查和差异检查通过。

### 默认扣减与手动调拨的实现规则

用户已选择“默认存储扣减＋手动调拨”，并补充未指定时的有限自动吸收。每个预算单独配置默认扣款存储，普通消费与完整支出冲销事项按净额扣减，负净消费返还到同一存储；收入事项的分出不重复扣。特殊消费可以在第六页单独改选存储或恢复默认。默认设置影响该预算全部未单独指定的消费，保存前明确说明。没有默认和例外时，不再把整笔消费直接放进待归属：先扣待分配，再扣启用的顶级“活期”，仅将余额不足的差额保留为待归属。

“待定存储方式”已取消。它原本是一条真实存储占位明细，而“待分配”是 `预案总额－实际存储分配` 的派生余额；在当前先填总额、再按需分配的流程中，两者都表达尚未决定存储去向，没有必要同时保留。升级时删除当前计划中引用占位存储的明细：已有明确总额保持不变，原占位金额自然回到待分配；旧计划尚无明确总额时，先按迁移前全部明细合计固化总额，再移除占位明细。当前计划版本递增，历史版本快照继续保留原名称与金额，账户、流水、预算总额和已分配到真实存储的金额不变。迁移前备份为 `finance-pre-unallocated-storage-*.db`。

- 交叉总表新增“截至所选月剩余”，作为默认查看范围；本月计划及累计安排继续可选。余额从预算执行起算月连续计算，忽略计划累计起始月筛选。期初预算余额与尚未安排的预算进入“待分配”；消费未指定扣减来源时依次使用待分配与启用的顶级“活期”的正余额，差额单列“待归属消费”。命名存储、待分配及待归属消费的有符号合计必须等于预算执行结转余额。
- 新增独立的默认存储、消费例外归属及存储调拨记录，金额沿用预算唯一币种。调拨按生效月份记录，只能在同一预算内、不同存储（含待分配）之间转移正数额度；转出额不能超过该月转出项当前剩余。明确归入某个存储的消费仍允许将该存储扣成负数；未明确归属的消费只自动使用待分配与活期的正余额，剩余差额留在待归属，不自动从 ETF 等补足。可以在页面更正或撤销调拨，保留审计与备份；更正、历史数据变化后可能出现负余额，继续明确提示。
- 消费例外引用当前普通支出或完整支出事项及其当前预算，不修改原始流水。事项重新组织、改变方向或移到其他预算后，不把旧身份的例外强套到新事项；新身份按默认归属，用户可再次指定。账户、第三页查询及原有冲销统计不变。
- 消费使用现有汇率与统计日期。每预算每月先计算完整净支出，按最小单位分配舍入尾差到该月消费，使存储扣减合计与执行表一致；负净额和零净额保留。缺汇率、主方向跨预算或旧多币种时显示不完整，不以已知部分冒充余额，也不能据此增加调拨。
- 调拨、默认和例外归属采用写事务及配置版本检查；币种更正同步保留调拨可见数字并核验目标精度，原币种信息写入审计。停用存储保留余额与已有引用，仍可调出，新增调入需选有效存储。新表创建前备份，不改写已有计划或真实流水。
- 第六页提供“管理扣款与调拨”弹窗：默认扣款、所选月消费归属、调拨录入及历史修改在同处维护；主表展示存储缺口、自动吸收结果和待归属差额，保留金额明细点击及交换行列。Excel 追加存储剩余和调拨记录，原计划表保留。

实现结构：`budget_storage_defaults` 保存每预算默认扣款，`budget_storage_expenses` 保存当前普通消费或事项的例外存储，`budget_storage_transfers` 保存同预算内按月生效的调拨、币种、金额和版本。`app/budget_storage.py` 负责余额投影与事务校验；`GET /api/budget/storage/{system_id}/{month}` 同快照返回余额、当月消费、此前调拨及设置版本，`PUT .../default`、`PUT .../expense` 和 `POST/PUT/DELETE .../transfers[/id]` 维护记录。消费例外另外校验当前事项令牌；缺汇率、主方向跨预算及待归属消费未整理时不能据此新增调拨。

迁移备份为 `finance-pre-storage-balances-*.db`。调拨、默认及例外写入都备份，并把修改前后数据与配置版本写入审计；币种更正也同步重编码全部调拨，数字不变，精度不符整体回滚。余额逐月使用执行表相同的舍入总额，再按余数大小和稳定身份分派最小单位，使各存储之和与预算执行严格一致；单笔显示金额可能受该月的最小单位尾差分配影响。Excel 剩余和调拨与概览使用同一读取快照。

本轮验收：75 项后端测试通过，包含默认归属、负存储余额、跨月 AA 返还、收入事项排除、特殊消费、精度尾差、缺汇率、调拨版本与撤销、币种回滚、迁移备份，以及调拨不释放收入来源额度。隔离桌面四组回归（原预算与记账查询、历史月份及币种、收入绑定、存储维护）通过，截图已核对；存储弹窗在保存失败和月份输入框聚焦时的 Esc 草稿保护已专项验证。原计划金额、账户余额、流水查询与导出继续保持一致。

## 预算结余与跨月传递（已实现）

第六页已新增由计划与实际流水共同计算的执行视图，原计划记录仍独立保存。计划金额、存储已分配和待分配继续保留；待分配不等于消费后的剩余。

用户明确确认“所有预算都连续结转”，包括日常预算，不设置每月清零或每个预算单独选择是否结转的选项。按每个预算连续计算：`本月可用 = 上月结余 + 本月新增预算`；`月末结余 = 本月可用 - 本月净支出`；下月期初承接该结余。正数和负数都自动结转，月末核对无需复制余额或生成结转流水，修改历史月份后重新计算后续结果。

- 当月没有编制计划时，计算暂按新增零处理，同时明确显示“未编制”，不冒充已确认的零预算。即使没有当月计划，仍纳入该预算的消费；若已有结余足够支付，就不会变成负数。
- 若上月结余为零、当月新增为零但有消费，形成负结余并减少下月可用额度。负数是计算结果，不要求录入负的月计划金额。
- 消费复用冲销后支出口径，退款参与原事项净额，避免垫付部分重复扣减；跨币种折成预算币种。缺汇率或主流水跨预算时显示未完整计算，不能将漏算结果当准确余额。具体汇率口径见下方实现规则。
- 普通收入不会再自动增加预算，新增预算由用户填写，避免将同一份工资重复计入；转账、换汇及存储分配也不自动当作消费。
- 执行起始月及期初结余可以在设置中维护，默认规则见下方。只纳入该预算的有效归属支出；首次使用及历史数据不完整时保留说明，不预设真实资金余额。
- 查看某一个月或筛选一个区间，不得将更早月份的结余误清零；执行表及 Excel 同步使用这一规则。

### 本次实现规则

- 起算默认取本预算最早计划月与最早有效支出事项月中的较早者，期初为零；设置页允许指定起算月及有正负号的期初结余，须配套指定预算币种。这是预算执行的起点，不是账户期初余额。查看区间只裁剪展示，不丢弃更早结余。
- 净支出使用完整冲销事项及未冲销支出；按事项统计月归属，跨月返还仍参与原事项。逐笔按原日期的账本快照折算，优先当天、否则最近日（等距优先较早日），不查询实时汇率。支持账本有报价的 CNY/HKD/USD 互算；其他币种支持原币直接计入，无法跨币换算时明确标缺失。
- 同月净支出先以 Decimal 合计，再按预算币种精度四舍五入；每月以最小单位连续计算结余。缺汇率或主方向跨预算时，本月支出或结余标为未完整计算，并传递到后续月份，不把已知部分冒充余额。普通收入、转账、换汇、买入资金的内部移动和存储分配不重复增加或扣除预算。
- 公共存储迁移先备份，保留分配明细 ID 与历史快照。完整路径、启用状态、说明一致的旧栏目归并；同名但状态或说明不同的栏目保留原预算名后缀，避免误合并。旧 ID 保留映射以兼容旧快照和已有客户端，公共目录的新 ID 不复用旧 ID。
- 第六页新增执行表：上月结余、本月新增、本月可用、净支出和结转余额；可展开月度历史，未编制仍纳入消费并显示提示。存储总表继续展示计划，不把已安排存储当支出。Excel 同步包含执行结果与完整性说明。
- 验证使用隔离账本，覆盖迁移及旧快照、公共栏目跨预算使用、负结转与无计划消费、跨月冲销、历史修改、汇率缺失及混合事项、日期边界及基础记账查询。

## 收入来源绑定与预案弹窗（已实现）

最新实现：第六页新增、编辑预案已改为桌面弹窗。每份预案可绑定一个收入来源，使用预案已有总额作为占用金额；同一来源可供多份预案使用，但合计不得超过来源净收入。

此前讨论的独立收入分配表、金额/比例两种分配模式、多来源共同支持一份预案及双重实际/计划结余，不作为本轮实现要求。预算继续使用现有手填总额与净消费结转，增加来源追溯及额度约束即可；下方规则替代前面的复杂分配提案。

### 净收支口径保持不变

- 收入事项按到账减分出的净收入统计，也可表达用户希望扣除聘用成本后查看的工资或项目收入。已冲减收入的分出不再次算作净消费。
- AA 等支出事项按付款减收回的净消费统计，回款不成为预算的收入来源；普通未关联收入、支出保持原方向。
- 原始流水、账户余额、原始导出不因预算绑定而变化。冲销继续保留有符号净额，不因预算额度需求截断负数或重新分类。
- 绑定显示的来源净收入用于核验预案资金依据，不额外加进预案总额，不重复扣减收入事项内已经分出的支出。

### 预案绑定收入来源与额度校验

**关系与金额：**

1. 一份预案指一个预算系统在某个月的整份计划；币种继承预算系统。每份预案可暂不绑定，绑定时至多选择一个来源。
2. 来源可选未参加任何冲销事项的普通收入，或一个收入冲销事项。选收入事项时使用整个事项的当前净收入，事项内的单笔收入不可再独立占用同一资金。
3. 一个来源可以绑定多个预算、多个不同月份的预案。原始收入不拆成多条流水，不要求新增分配表或再次填写分配金额。
4. 每份已绑定预案直接按其当前总额占用来源额度；ETF、定期等二级存储安排不另占一次。未明确总额的旧预案应在绑定前先确认总额，不能无提示地把部分存储明细当成完整预案。
5. 未绑定预案仍可正常保存和参与现有预算结转，但明确标为“未绑定来源”，不能声称它已经通过真实收入额度核验。

**同币种校验：**

```text
编辑当前预案可用额度
= 来源当前净收入
− 其他所有已绑定预案的总额

本次绑定/调整后预案总额 ≤ 编辑当前预案可用额度
```

合计涵盖全部预算与月份，只计算各预案当前有效版本，历史版本不重复占用。编辑时排除当前预案原占用，再验证新总额，防止保存同一个预案被算两次。

例：来源净收入 10,000；日常预案绑定 4,000，慈善预案绑定 1,000，还可绑定 5,000。留存预案若填写 6,000，禁止绑定并提示“可用 5,000，超出 1,000”；改为 5,000 后可以绑定。所有金额只在对应预案中填写一次。

**桌面操作：**

- 在预案编辑处增加可选“收入来源”，可搜索普通收入或收入事项，查看净额、日期和原始组成。
- 选中来源后显示来源净收入、其他预案已占用、本预案金额及绑定后的剩余额度，并能查看占用清单、跳转至原流水或事项；占用清单列出预算名称及月份，方便回到对应预案调整。
- 额度不足时不能确认绑定；保留当前草稿，明确差额及调整入口，不能自动截小预案。原有未绑定计划不会因尝试绑定失败而丢失。
- 对已绑定预案调大总额、替换来源时重新校验；失败保持原绑定和原已保存金额。若希望保留超出来源的计划，可主动解除绑定后作为未绑定预案保存。
- 不增加每个存储子项的来源选择。用户仍只维护预案总额、可选来源以及原有存储分配。

### 绑定后的修改与结转

配套处理规则：

- 调小预案或解除绑定时释放对应来源占用；解绑不删除收入，也不取消原预算计划。更换来源要在同一事务中完成，失败不能留下旧来源已释放、新来源未绑定的半成品。
- 日常消费、AA 退款及预算余额结转不会释放收入来源占用。已消费不是资金再次可分配；上期剩余直接结转，不需在新月重复新增或绑定同一笔额度。预算月份改变也不能让已占用金额重新可用。
- 来源增加时，只增加可绑定余量，不自动调大预案。来源因新增分出、原流水纠错或汇率调整而减少时，允许如实记录真实收支；若既有预案合计超额，标明来源缺口及受影响预案，禁止继续增加占用，由用户调小、换来源或解绑。
- 来源不足时原预案总额、存储安排及历史版本保持原样；执行表仍能给出按计划计算的结余，但须提示来源额度不足，不能称为已经核实的实际资金余额。
- 来源缺少汇率、无法完整计算、净额为负或引用失效时，不允许新增正数占用，并提示已有绑定待处理；原始收入和冲销统计不因而变成零。
- 有绑定的普通收入加入事项或删除、有绑定的事项解散或改变方向时，提示受影响预算及月份，须先解除绑定再操作。不能让原流水和新事项两边同时提供额度，也不能静默删除旧绑定或改写计划。

### 兼容性

- 预算继续计算“上期结余＋本月手填新增－净消费”，所有正负结余连续结转。绑定是来源核验，不生成额外收入，不把净工资自动重复加到预案金额上。
- 现有流水预算标签和第三页筛选保留原含义，标签本身不占用来源额度；绑定不会改写收入或分出支出的预算标签。
- 绑定的是已有预案，因此归入月份沿用预案月份，不另填分配日期；来源日期后改时提示核对，不自动移动预案。
- 单个预算仍只有一种币种。跨币种先将占用金额折到统一来源计价币种再校验，不能把 CNY、HKD 数字直接相加。采用已有汇率并展示计价币种、参考日期及邻近日期提示；具体折算和舍入规则见下方实施决策，不改写历史计划数字。
- 只需新增预案与来源的绑定关系及历史信息，当前预案总额就是占用依据，无需另一套可独立编辑的分配金额。来源使用普通收入/收入事项的互斥引用；每个预案只能有一个有效来源，所有校验需要事务和版本检查，防止多个窗口同时超额绑定。
- 旧预案默认未绑定，保留全部金额、来源标签和存储安排；实现升级须先备份，不能根据金额相近自动推断资金来源。

验证范围：一来源多预案、跨预算和跨月份额度合计、编辑不重复占用、调大超限拦截、解绑与更换来源回滚、净额后续下降、AA 回款排除、事项成员不可再选、来源生命周期变化、并发预览过期、跨币种及精度、预算结转与基础记账兼容。验证使用隔离账本，不修改真实账本。

### 本次实施决策：绑定与桌面弹窗

- 在现有月预案写入中一起保存来源绑定，省略绑定字段的旧客户端保留原绑定，明确空值才解绑。来源变化与其他预案占用采用预览版本校验，保存时再次在同一写事务核对全部月份的占用；失败回滚整份计划。
- 来源计价币种首次绑定时采用最早主收入的原币种，仍存在绑定期间保持固定；全部解绑后重新选择才按当时主收入决定。净收入按每个原成员的日期折到该币种；预案额度按事项统计日（普通收入即原日期）的已保存当天或最近汇率折到来源币种，等距优先早日。来源净额按该币种精度四舍五入，每份占用向上取整到最小单位，避免分笔舍入超配。界面展示日期、计价与邻近汇率提示；原计划数字不换写。之后汇率修订会重新核验并显示不足。
- 为防止同笔资金同时成为普通收入与事项来源，有绑定的普通收入在加入事项或删除前先解除预算绑定；有绑定的收入事项在解散、改成支出事项前同样提示先解绑。金额、日期及收入事项成员修正仍可进行；变动后显示超配或不可计算状态，不阻止如实纠错。减少预案占用允许逐步修复已存在的超配，新增或增加占用不得超限。
- 已绑定预算更正币种时，按更正后的预案数字重新核验全部受影响来源，超限整体回滚并指出来源；可先调整总额或解绑。历史版本记录当时的来源信息，复制其他月份只复制计划与存储，保留目标自身的绑定、不继承来源月份的绑定。
- 主页面保留月份筛选、概览、各预案及来源状态、执行结余和存储总表。编辑区移入有标题、关闭按钮及固定操作区的大弹窗，内部滚动，背景位置保持不变；新增与编辑共用弹窗，保存成功关闭并刷新概览。关闭、Esc、切换预算身份遇未保存草稿时提示；点击遮罩不丢草稿，保存期间防重复操作，保存失败保留弹窗、错误与草稿。
- 弹窗内依次为预算身份、总额/币种、可选收入来源、二级存储安排；复制、历史和币种更正保留。来源选择可搜索普通收入/事项，展示净额、已占用、当前预案可用及占用清单；选择失败或额度不足不清空输入。旧多币种计划继续只读，电脑端验收不涉及手机布局。
- 迁移新增绑定表前备份，真实账本不用于测试。后端覆盖额度、来源生命周期、币种更正、历史兼容；桌面覆盖保存关闭、失败留窗、Esc 草稿保护、搜索来源、跨预算共享额度、复制与原有记账查询回归。

实现结构：`budget_plan_funding` 每份计划仅一行，普通收入与收入事项外键互斥，保存来源计价币种，无独立占用金额。`GET /api/budget/funding-sources` 提供搜索分页及单来源预览；计划写入中的 `funding` 为来源类型、ID 和 `expected_token`，显式 `null` 解绑。单计划、月计划、币种更正都在写事务中校验来源额度。历史版本保留保存时的来源快照，Excel 总额表追加来源及状态；执行表及执行导出提示历史来源不足，但不改动计划结转算法。旧数据库首次升级先备份为 `finance-pre-budget-funding-*.db`。

验证结果：66 项后端测试通过，新增来源用例涵盖共享额度、版本过期、净收入变化、AA 排除、跨币种向上舍入、缺汇率、币种更正回滚及升级备份。`budget_browser.cjs`、`budget_history_browser.cjs`、`budget_execution_browser.cjs` 和 `budget_funding_browser.cjs` 四组桌面回归通过；弹窗内新增存储控件重叠已修复，保存关闭、失败留窗、键盘焦点和草稿保护均已验收，原始记账、账户选择、流水查询、冲销与导出保持可用。

## 2026-10-02 修正：每个预算系统只有一种币种（当前规则）

上一版误将币种设计成月度预案下面的多个金额组，并锁住已保存币种。本次改为：**预算系统确定一种预算币种，各月份总额、二级存储分配均继承该币种**。不同预算系统可以使用不同币种；同一系统不能因消费币种不同而拆出另一份计划。

- 预算页每月只填一个总额；新系统首次编制时可在金额旁选择币种，之后自动沿用。设置页也可指定预算币种。

- 更正数字时按照目标币种重新编码最小单位，不能把分直接当元。目标精度不支持原数字时拒绝并指出月份，要求先调整该月金额，不静默四舍五入。修改有备份、全量计划版本检查，任一校验失败全部回滚；其他窗口的旧草稿不能覆盖新币种。
- 升级只增加系统币种配置。历史只有一种币种的系统自动继承；尚无计划的系统在首次设置或保存时确定。若旧系统确有多币种，原计划和统计完整保留，并标为待整理、暂停新增或改写，不静默合并金额或删除记录。
- 实际流水保持原始币种和金额，预算归属仍只选择预算系统。执行视图将跨币种净支出折成预算币种进行比较，不要求建立对应外币预算，也不改写计划总额。
- 验证：币种可修改、跨月统一、原数字及精度、历史快照、并发与回滚、旧账本备份及多币种兼容；电脑端历史月份、复制、设置、总表及导出；原始记账、账户余额、流水查询、冲销回归。

实现验证：51 项后端测试通过；隔离账本上的电脑端完整回归与历史月份 / 币种更正专项回归通过。设置页和预算页均可更正已有币种，未改写正式账本金额。

例：九月“慈善”预算 `1,000 CNY`，其中 ETF `600`、定期 `300`、待分配 `100`。新增时总额只填一次；之后调整二级分配时，预算总额仍为 `1,000`。

## 1. 首版范围（旧设计，以上方模型修正规则为准）

用户明确要求：

1. 第六页只有预算计划，不涉及真实值。
2. 每个月可以自行新增预算数值，也能修改当月计划。
3. 可以在页面上新增栏目、细化层级，提前安排每一笔预算的存储方式和使用方式。
4. 栏目管理和预算编辑均通过前端操作，不要求手工修改数据库。
5. 有总表查看 ETF 等存储方式的预算合计，以及其中分别安排给慈善、留存等用途的金额。
6. 支持多套可命名预算系统，例如日常预算、专项预算；分别编制月计划。实际收支可以单独标记预算归属，在第三页筛选。

本版用这些澄清替代上一稿的实际资金归属、投资份额、估值分摊、收益归属、对账和执行率设计。之前关于实际收益如何归属的待确认问题已不适用。

第六页独立记录计划，不读取真实收入、支出、账户余额、冲销净额或投资估值作为预算金额；不生成流水，也不要求先创建账户、录入收入或拥有相应资产。流水可引用同一个预算系统，供第三页查询实际消费；这种归属标记不会自动扣减或改写计划金额。预算默认项、分类映射、首页三种模式分离与统计规则见 [预算归属与设置设计](budget-attribution-and-settings-design.md)。

例如“慈善 × ETF：500 元”只表示计划将 500 元安排到这个组合，不表示已经买入 ETF 或拥有 500 元市值。

## 2. 两个独立、可自定义的维度

| 维度 | 回答的问题 | 示例 |
| --- | --- | --- |
| 存储方式 | 这笔预算准备怎样存放或配置？ | 活期、定期、ETF、股票 |
| 使用方式 / 用途 | 这笔预算准备拿来做什么？ | 日常生活、慈善、留存、学习 |

建议界面简称“存储方式”和“用途”。两者地位相同，都保存到数据库，各自形成一棵可管理的分类树，通过预算明细关联。预算系统是这两套栏目的上层容器；每个预算系统独立管理栏目和计划，可从另一系统复制配置，复制后独立修改。

一条预算明细的基本结构为：

```text
预算系统 + 月份 + 币种 + 存储方式 + 用途 + 预算金额 + 明细名称 / 备注
```

例如：

| 月份 | 存储方式 | 用途 | 明细名称 | 金额 |
| --- | --- | --- | --- | ---: |
| 2026-10 | ETF | 慈善 / 教育助学 | 助学储备第一笔 | 300 |
| 2026-10 | ETF | 慈善 / 教育助学 | 助学储备第二笔 | 200 |
| 2026-10 | 定期 / 三个月 | 留存 / 应急 | 应急计划 | 1,000 |

前两笔可以保留各自说明，矩阵中的“ETF × 教育助学”自动合计为 500。第一版允许多笔预算明细，不强制一个格子只能存一条记录。

同一笔金额通过两个维度查看，不存成两份分别累计。例如“慈善中的 ETF 500”与“ETF 中的慈善 500”是同一条计划。

## 3. 每月新增、修改与累计

### 3.1 建议采用“当月新增预算”作为录入值

用户每月创建一份计划，输入本月准备新增的预算金额，系统提供月度与累计两个视图。

```text
上月累计预算 = 起始月份至上月各月最新版本预算的合计
本月新增预算 = 本月预算明细的合计
截至本月累计预算 = 上月累计预算 + 本月新增预算
```

以“慈善 × ETF”为例：

| 月份 | 上月累计预算 | 本月新增预算 | 截至当月累计预算 |
| --- | ---: | ---: | ---: |
| 2026-10 | 0 | 500 | 500 |
| 2026-11 | 500 | 300 | 800 |
| 2026-12 | 800 | 200 | 1,000 |

输入十一月的 300，代表新增预算 300，不代表把累计目标改成 300。界面必须标明“本月新增”，不使用含糊的“金额”让这两种含义混淆。

所有累计数字均为**累计安排过的预算**，不代表尚未花掉的金额、实际持仓或资金余额。即使每月安排餐饮预算，年度合计也只是全年餐饮计划总额，不会根据真实消费自动扣减。

累计范围可选起始月份与截至月份；未来月份可提前编制，但不会加入更早月份的累计结果。没有创建计划的月份显示“未编制”，不能声称已有明确的零预算。

### 3.2 修改不会重复增加

- 将十一月 300 改成 350，是修订十一月计划，累计改为 850。
- 再次点击保存相同内容，不会再增加 350；保存需识别当前计划和明细 ID。
- 在十一月再新增一条 50，是另一笔新增预算，原有 300 保留，当月合计为 350。
- 把某条预算从 ETF 改为定期，是修改存储方式；该条金额保持一份，整体总额不变。
- 删除某条预算会从该月及其后的累计中移除其金额，保留修改记录。
- 修改旧月份会重算受影响的累计。保存前提示“将修订某月计划及后续累计”，历史版本仍可查看。

建议第一版明细金额非负；减少某月预算时直接改小或移除明细，不用负的新增金额来表示支出、亏损或提款。

如以后希望“保持旧月计划不变，但本月撤回或重新安排过去累计的预算”，需要独立的计划调整记录。本版不把这种动作混入新增预算，也不把累计视图当作可以随意覆盖的数字。

### 3.3 每月创建与复制

2026-10-01 历史月份编辑入口补充：编制月份可选择任意历史月份，选月后直接加载该月计划；提供“上个月 / 下个月 / 回到本月”快捷入口。九月未编制时可补录，已有计划时可修改原明细或追加新明细。编辑标题和保存按钮显示具体月份，保存仍修订该月唯一计划，并更新后续累计，不改写其他月份的明细。

切换前有未保存草稿时确认是否放弃；取消或加载失败时恢复原来的月份及筛选项，并保留草稿。切到早于累计起始月的月份时清空累计起始月，以便直接补录旧月。新记录、修改和追加均沿用已有版本检查及历史版本，无须迁移数据库。

“新建月份”提供：

1. 空白计划：选择月份、币种，逐笔添加预算。
2. 复制某月：复制栏目选择、明细说明与计划金额，预览后保存为新月份。

不会默认把上月累计金额再复制为本月新增金额。未保存的复制预览不进入统计；同一预算系统、月份、币种已有计划时，打开编辑，不重复建第二份并相加。月度与累计查询均限定所选预算系统，不混入另一套预算。

可选填写“本月预算总额”，完全由用户手填；不从实际收入自动取值。

```text
本月已安排 = 本月全部预算明细合计
尚未安排 = 本月预算总额 − 本月已安排
```

未填写总额时，只显示已安排数，不把总额当成零。已安排超过总额时显示“超出计划总额 X”，允许保存这一明确的计划差异，不宣称这是实际资金不足。

固定金额是第一版基础输入。比例分配若后续加入，只针对用户手填的计划总额生成可编辑明细，不依赖实际收入。

## 4. 新增栏目和更细粒度划分

### 4.1 页面提供的管理操作

在独立设置页提供“管理存储方式”和“管理用途”，第六页保留管理入口并带上当前预算系统，支持：

- 新增顶级项目。
- 新增子项目。
- 修改名称与说明。
- 调整显示顺序、展开或折叠。
- 停用项目，停用后不出现在新预算的可选项中，历史计划仍可查看。
- 删除从未使用且没有子项的项目；有预算引用时使用停用，保留关联。

预算明细选择器里也提供“＋新增存储方式 / 用途”，创建成功后立即可选，保留正在填写的金额和其他内容。

页面中新增一列或一行，本质上是新增一个分类记录。用户不需要写 SQL、修改数据库字段或修改前端代码。

### 4.2 层级例子

```text
存储方式                      用途
├─ 活期                       ├─ 日常生活
├─ 定期                       │  ├─ 餐饮
│  ├─ 三个月                  │  └─ 交通
│  └─ 一年                    ├─ 慈善
├─ ETF                        │  ├─ 教育助学
│  ├─ 宽基                    │  └─ 其他捐助
│  └─ 债券                    ├─ 留存
└─ 股票                       │  ├─ 应急
                              │  └─ 大额支出
                              └─ 学习
```

新预算填写在末级项目，父项目由子项汇总。折叠“慈善”时显示其合计，展开时显示助学和其他捐助；父合计不与子项再相加。

如果某个已有金额的末级项目后来增加子项，旧预算保留在原项目 ID 上，累计视图单列“原有未细分”部分。不能自动认为它全部属于某个新子项，也不能因新增子项使旧金额消失。用户可以打开相应月份，自行将旧明细拆分到子项，保存为该月的新版本。

同一父项目下不允许同名，同一个维度内禁止循环层级；不同父项目下同名时，选择器显示完整路径，例如“慈善 / 教育”和“个人 / 教育”。

### 4.3 改名、层级与历史

- 用稳定 ID 关联预算，改名不会让预算失去关联。
- 保存月度计划时保留该版本使用的栏目名称和层级快照，查看历史版本仍能看到当时的结构。
- 跨月累计默认按当前栏目结构整理，明确标为“按当前栏目汇总”；历史停用项目保留显示，不能被默认过滤掉金额。
- 改层级只改变当前汇总归组，不改变预算金额、月份或原币。
- 改名或调整层级前预览受影响范围；不需要用户手工迁移数据库。

## 5. 总表及直接编辑方式

建议总表默认用途为行，存储方式为列，也可切换行列。两种方向只是展示方式，数据库结构不变。

以下为某月计划金额示例，全部为手填预算：

| 用途 \ 存储方式 | 活期 | 定期 | ETF | 股票 | 用途合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 日常生活 | 3,000 | 0 | 0 | 0 | 3,000 |
| 慈善 | 200 | 300 | 500 | 0 | 1,000 |
| 留存 | 800 | 700 | 500 | 0 | 2,000 |
| 自用投资 | 0 | 1,000 | 2,000 | 1,000 | 4,000 |
| **存储方式合计** | **4,000** | **2,000** | **3,000** | **1,000** | **10,000** |

由此可知计划分给 ETF 共 3,000，其中慈善 500、留存 500、自用投资 2,000。行列合计是同一批明细的汇总，不能相加成 20,000。

支持两种查看范围：

- **本月新增预算**：矩阵显示所选月份明细的合计。
- **累计预算**：显示所选月份区间的累计计划，点击可按月份追溯。

点击单元格打开该组合的明细面板，可新增一笔、修改某笔或删除某笔。若格子内有多笔，不能通过直接覆盖合计数悄悄丢掉明细；需要明确编辑具体明细或使用可预览的批量替换。

空格可直接点“新增预算”；未填写和显式零预算在明细中区分。暂未决定存储方式的金额直接留在“待分配”，不再建立“待定存储方式”明细；旧用途标签仍可使用系统保留的“待定用途”，之后在页面补全。

固定的月份、币种、名称、金额、备注之外，本轮支持自定义的是两套行列项目及子项。不把任意新文本字段、第三维度或公式列都做成表结构编辑器；将来需要其他维度时再设计。

## 7. 数据库设计建议

### 7.1 两种栏目都入库，分别保存

采用关系表结构：预算系统表、两张栏目表、月计划表、明细表及版本记录，建表语句位于 `app/budget_schema.sql`。

| 表（建议名称） | 主要字段 | 职责 |
| --- | --- | --- |
| `budget_systems` | `id, name, sort_order, is_active, note` | 日常、专项等预算系统 |
| `budget_storage_methods` | `id, budget_system_id, parent_id, name, sort_order, is_active, note` | 某预算系统的存储方式及层级 |
| `budget_purposes` | `id, budget_system_id, parent_id, name, sort_order, is_active, note` | 某预算系统的用途及层级 |
| `budget_plans` | `id, budget_system_id, month, currency_code, total_minor（可空）, version, note` | 每系统、每月、每币种一份计划 |
| `budget_plan_items` | `id, plan_id, storage_method_id, purpose_id, title, amount_minor, sort_order, note` | 用户逐笔填写的预算金额 |
| `budget_plan_revisions` | `plan_id, version, snapshot, created_at` | 修改前后版本及当时的栏目名称、路径 |

金额只保存在明细中；矩阵、父项合计、月合计和累计结果由查询计算，不让用户另外维护重复的合计数。本月预算总额是用户独立填写的目标，所以单独保存，不能与明细合计再相加。

一个明细有一个存储方式 ID 和一个用途 ID。需要一笔预算拆成多个组合时，拆成多条明细；可以使用相同名称说明它们属于同一计划项目。

不设计 `活期金额`、`定期金额`、`ETF金额`、`慈善金额` 等固定数据库列，也不为每个月或每种栏目创建新表。新增“黄金”只会增加一条存储方式记录，所有查询和页面通过数据自动生成栏目。

两维都保存到 SQLite，而不是把其中一维写死在前端或只放在浏览器本地：这样刷新、换浏览器、备份恢复和历史汇总都能完整保留。

### 7.2 数据完整性与易维护性

- 预算系统、月份和币种组合唯一；预算明细引用同一系统中存在的栏目 ID，防止串用不同系统的栏目。父子栏目也必须属于同一系统。
- 同一个组合允许有多条有各自 ID 的明细；修改时定位明细 ID，不按金额猜测记录。
- 金额按币种最小单位保存整数，不使用浮点数直接累计。
- 用户新增、改名、停用、拆分等动作通过后端统一校验，同一次操作在一个数据库事务中完成。
- 更新使用版本检查，防止两个浏览器页面的旧内容互相覆盖；重复保存或重试不能重复插入预算。
- 首次保存和后续修改保留可查看版本，删除或修改预算有审计；复用项目已有备份约定。
- 删除被引用的栏目由外键阻止，界面提供停用，保留历史；系统“待定”项目不能删除。
- 版本快照用于保留历史，不替代主明细表，不把整套可查询预算仅存成一个不透明 JSON。

“数据库干净”主要来自统一数据结构、稳定关联和页面校验，不是让用户少建几个真正需要的栏目。

### 7.3 与现有表隔离

现有 `monthly_budgets` 是“月份 × 真实支出分类 × 币种”的生活支出预算，已经用于既有 Excel 对比。新的预算是“月份 × 自定义用途 × 自定义存储方式”，语义不同，建议使用独立命名的新表。

不将预算用途直接塞入现有 `categories`；不将计划 ETF、定期等创建成真实 `accounts`。真实流水可关联 `budget_systems` 作为统计标签，但不强制关联某月计划、计划明细或存储方式，不引入资金占用和估值计算。本轮不迁移、删除或改写已有 `monthly_budgets`，也不改变其导出逻辑。新预算导出使用明确的“预算计划”表名，避免与既有预算执行表混淆。

币种可复用 `currencies` 字典，但每份计划采用一个币种。跨币种累计分币种显示，不直接相加；第一版不依赖真实汇率。若未来需要折算计划，由用户明确设置预算汇率及其版本，另行设计。

## 8. 实现边界与验证场景

已实现独立预算服务 `app/budgets.py` 与前端 `static/budgets.*`、`static/budget-ui.js`，从服务端统一生成月度、累计和矩阵数据；模块不依赖实际收支统计服务或投资收益服务。设置管理位于 `static/settings.*`。矩阵支持展开明细、按一级栏目汇总与交换行列，点击金额可追溯或跳转到所属月份编辑；逐笔移除和修改在月明细表进行。

最小完整功能包括：月计划编辑、自定义两维栏目及层级、逐笔预算、本月 / 累计矩阵、修改版本、页面内栏目管理。不能只交付几个固定栏目就视为满足可自定义需求。

验收场景：

| 场景 | 预期 |
| --- | --- |
| 无真实账户或流水 | 仍可创建完整预算 |
| 十月新增 500，十一月新增 300 | 十一月累计 800，不需要再手填 800 |
| 将十一月 300 改为 350，再重复保存 | 累计 850，不会重复加 350 |
| 同月同组合添加 300 和 200 两笔 | 格子合计 500，展开仍有两笔 |
| 复制十月计划到十一月 | 预览后保存，复制的是当月明细，不是十月前全部累计 |
| 新增“黄金”或“慈善 / 助学” | 页面出现可选栏目，无需改数据库字段或代码 |
| 改名、停用已经被使用的栏目 | 历史引用完整，累计不丢金额，旧版本保留当时名称 |
| 已有父项目后来增加子项 | 旧金额显示为未细分，父子不会重复统计 |
| 将预算从 ETF 改到定期 | 总额不变，对应列合计重新分布 |
| 总额未填 / 明细超过目标总额 | 分别显示未设总额或超出计划，均不冒充真实资金状态 |
| 累计截至十一月，十二月已经编制 | 不包含十二月金额 |
| CNY 与 HKD 同期都有计划 | 分币种汇总，不直接混加 |
| 修改真实流水、冲销关系或投资估值 | 本页计划金额不自动变化 |
| 修改或新增预算 | 前五页实际收支、账户资产和投资数据不变化 |
| 同月编制日常和专项两份预算 | 彼此独立，栏目和累计金额不串用 |
| 实际支出标为日常预算 | 第三页可筛选，日常预算计划数不自动扣减 |

## 9. 已定方向与后续细化

已确认：纯预算计划、多预算系统、按月可新增数值、可自定义两维栏目、前端管理、可细分、可查看交叉总表；新增实际流水预算归属与第三页筛选，默认预算可配置。

建议规则：按“每月新增”录入并提供累计；金额优先逐笔固定数值；复制计划须先预览；使用稳定 ID、层级栏目与历史版本保持数据清楚。

- `GET /api/budget/config`：预算系统、栏目、默认项、映射、预设及配置版本。
- `POST /api/budget/config/{collection}`、`PUT /api/budget/config/{collection}/{id}`、`DELETE ...?expected_version=`：维护设置；集合为 `systems/storage/purposes/rules/presets`。
- `GET /api/budget/config/{collection}/{id}/impact`：用途或存储栏目的受影响月份及明细数。
- `PUT /api/budget/defaults`：分别选择支出和入账默认预算。
- `POST /api/budget/copy-catalog`：复制另一预算的两套栏目到仅含待定项的新预算，复制后独立维护。
- `GET/PUT /api/budget/plans/{system}/{YYYY-MM}/{currency}`：读取或保存月计划；更新携带 `expected_version` 和已有明细 ID。
- `GET .../revisions`：该月各已保存版本，包含当时名称和路径。
- `GET /api/budget/summary`、`GET /api/budget/export.xlsx`：参数为 `system_id/end_month/currency_code` 和可选 `start_month`，范围与币种一致。

月度目标和每月明细合计最多支持 `10^15` 个币种最小单位；累计在服务端用整数、前端用 BigInt 从十进制金额字符串求和。Excel 金额为数值单元格，用户填写的名称和说明按文本导出。

新账本的公共存储目录只预置活期、定期、ETF、股票，不再预置待定存储；初始“日常预算”仍保留日常生活、慈善、留存等历史用途标签。新预算可复制用途栏目后修改。复制月计划仅生成草稿；来源中已停用或已细分的存储栏目不复制为占位金额，保存前须选择真实存储或将金额留在待分配。历史版本只读，当前版本允许修改和清空明细。

验证使用临时数据库：`tests/test_budgets.py` 覆盖迁移、版本、精度、层级、跨预算校验、统计与冲销；`tests/budget_browser.cjs` 配合 `tests/budget_browser_server.py` 验证实际页面操作。正式账本未用于测试。

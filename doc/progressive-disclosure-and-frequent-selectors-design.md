# 页面折叠、分类占比与常用选择设计

## 背景

当前页面功能已经覆盖记账、概况、流水查询、投资估值和汇率维护，但随着流水、账户和月度数据增加，页面存在三个可用性问题：

1. 第二页“概况与查看”的“账户内资金流动”明细表会随当月转账、换汇和投资资金移动增长，用户只想查看概览时仍需要越过完整表格。
2. 第三页“账户与流水”的“流水查询”虽然已有分页，但当前每页 50 条且查询结果始终展开；查询汇总的“按流水类型”也会在多类型筛选时拉长页面。
3. 第四页“投资与汇率”的“月度投资统计”按“月份 × 投资账户”展示，默认从当年 1 月到当前月自动查询，时间跨度和账户数增大后会明显拉长页面。

同时，账户数量已经超过日常使用范围。所有账户直接出现在每一个下拉选择中，会降低录入、转账和筛选效率。分类数量后续也会继续增长，需要区分常用选项和低频选项。

另一个具体需求是：第三页“流水详情”的“分类分布”除了金额和笔数，还应展示金额占比，并让数值列稳定对齐。

## 目标

本次设计分为三部分：

1. 对长明细采用渐进展示：保留关键信息可见，把低频、长列表或需进一步核对的内容折叠。
2. 在流水详情的分类分布中增加金额占比，帮助判断某一类流水的相对规模。
3. 建立可复用的“常用 / 其他”账户和分类选择模型，默认显示有限常用项，其他选项按需展开。

## 不在本次范围

- 不隐藏首页“记一笔”、第二页“最近流水”、第四页“录入投资估值”和“区间收益”这些高频或即时需要的区域。
- 不把账户或分类删除、停用，折叠只改变前端展示和选择效率。
- 不按交易金额、余额、账户名称、账户编号或人工排序字段推断“常用”；常用项只按本设计定义的近期真实流水计算。
- 不修改流水、账户余额、汇率、投资估值和 Excel 导出的业务口径。

## 一、长明细折叠方案

### 统一交互原则

使用原生 `details` / `summary` 作为可折叠容器：

- 键盘可操作，浏览器原生支持展开状态。
- 标题始终可见，摘要中显示关键数量或时间范围。
- 用户主动查询后产生的数据不丢失；关闭只隐藏内容，不重新请求数据。
- 对于默认折叠且请求成本较高的区域，在第一次展开时才请求数据。

不能仅通过 CSS 隐藏内容，也不使用没有语义的“展开更多”文字链接。

### 第二页：账户内资金流动

保留当前“账户内资金流动”的汇总卡片常显：

- 各币种内部转出。
- 各币种内部转入。
- 涉及笔数。

把明细表包入默认折叠的容器：

```text
账户内资金流动
2026-09 · CNY/HKD 汇总卡片

▶ 查看本月 12 笔资金流动
```

展开后显示现有日期、类型、资金路径、金额和备注表格。没有资金流动时，不显示可展开入口，直接显示“本月暂无账户内资金流动”。

这样用户查看月度收支、可用现金和净资产时不必越过内部转账明细；需要核对资金路径时再展开。

“最近流水”保持不变：它固定只显示最近 20 笔，位于页面末尾，长度和定位都可接受。

### 第三页：流水查询

第三页需要区分三种内容：

1. 查询筛选条件：始终展开。
2. 查询汇总：始终展开，作为筛选结果的关键结论。
3. 逐笔查询结果：折叠和分页。

#### 查询结果表

将“查询结果”表格改为 `details`，默认行为如下：

- 首次进入“流水查询”且尚未主动筛选：不展开。
- 用户点击“查询”后：显示摘要，但明细表默认折叠。
- `summary` 显示总笔数、当前页范围和当前页条数，例如：

```text
▶ 查询结果：共 126 笔，当前第 1 页（1-20）
```

- 页面大小从当前每页 50 条调整为每页 20 条。
- 翻页时保持查询结果区域展开，避免每次翻页都需要再次点击。
- 编辑、删除、标记后自动刷新结果、查询汇总和流水详情；若结果区域此前展开，刷新后继续保持展开。

20 条是本项目的初始固定值：足够一次浏览，又不会让表格占据整个页面。暂不增加“每页条数”选择，避免增加一个低价值设置。

#### 查询汇总中的按流水类型明细

“全部类型合计”保持展开；其后“按流水类型”改为默认折叠：

```text
▶ 按流水类型查看（支出 25 笔、入账 3 笔）
```

原因是这部分在选择多个类型时会重复显示“原币种明细”和“统一计价合计”，适合用于进一步核对，不应挤占逐笔查询和流水详情的首屏空间。

当只选择一种流水类型时，“按流水类型”与“全部类型合计”信息高度重复，可不显示该折叠区。

#### 流水详情

流水详情仍维持原有启用条件：完整日期范围、不超过 12 个自然月、只选择一种流水类型。日历、核心统计和直方图保持展开，因为它们是单类型分析的主要结果。

### 第四页：月度投资统计与每日汇率

“月度投资统计”改为默认折叠：

```text
▶ 月度投资统计
```

折叠时只显示标题和上一次查询状态；展开后显示筛选表单和结果表格。

请求策略：

1. 页面初始化时不调用 `/api/investments/monthly`。
2. 用户首次展开“月度投资统计”时，使用默认日期范围加载一次。
3. 后续修改月份或投资账户后，只有点击“查询月统计”才重新请求。

“每日汇率”继续位于第四页最后。它也改为默认折叠，摘要显示最近快照日期和已加载条数，例如：

```text
▶ 每日汇率：最近快照 2026-09-08，120 条
```

首次展开前不额外请求汇率元数据，摘要显示“展开每日汇率”；第一次加载完成后才替换为最近快照日期和已加载条数。

同步今天汇率和“手工覆盖汇率”只在展开后显示。这样汇率维护仍在页面末尾可用，但不会压缩投资估值、估值记录和区间收益的可见空间。

“估值记录”和“区间收益”本次保持展开：前者用于刚录入估值后的立即核对，后者是投资页的主要查询结果。

## 二、分类分布金额占比

### 统计口径

流水详情只允许选择一种流水类型，且所有成功换算的主金额均为非负金额。分类分布现有数据已经包含：

- 分类名称；没有分类时显示“未分类”。
- 分类金额，统一为 HKD。
- 流水笔数。

新增“金额占比”：

```text
分类金额占比 = 该分类换算后的 HKD 主金额合计 / 流水详情总金额
```

分母使用同一份 `statistics.total_amount`，即全部成功换算的流水详情主金额总额。因此：

- “未分类”也参与占比。
- 已被汇率缺失或不支持币种排除的流水不参与金额和占比。
- 所有分类金额占比之和在未四舍五入前为 100%。

### 展示与对齐

分类分布表调整为：

| 分类 | 金额 | 金额占比 | 笔数 |
| --- | ---: | ---: | ---: |
| 餐饮 | 420.50 HKD | 61.8% | 12 |
| 交通 | 131.20 HKD | 19.3% | 5 |
| 未分类 | 128.30 HKD | 18.9% | 2 |

规则：

- 金额占比保留 1 位小数。
- 金额、金额占比、笔数列均右对齐并使用等宽数字，列头与内容对齐。
- 分类名称左对齐。
- 只有一个分类时也显示该表，金额占比为 `100.0%`；现有“只有一个项目则不展示分布”的规则不再适用于分类分布。
- 账户分布和调整方向分布仍沿用金额与笔数，不在本次增加占比，避免页面产生过多重复比例。

## 三、常用 / 其他账户和分类选择

### 设计结论

原生 `select` 无法真正折叠其中一部分选项。因此不能只用 `optgroup` 标注“常用账户 / 其他账户”，因为打开后所有账户仍会同时出现。

采用可复用的“分层选择器”：

1. 初始菜单只显示常用项，最多 6 个。
2. 菜单底部有“其他账户（N）”或“其他分类（N）”入口。
3. 点击入口后，在同一选择面板中展开其余选项，菜单保持打开。
4. 已经选中的低频项必须始终显示在触发器中；再次打开时，它位于“其他”区域且保留选中状态。

初始上限设为 **6 个**：

- 比 3 或 4 个更适合多币种日常支付、转账来源和到账账户。
- 比显示全部账户明显更短，能在桌面和移动端快速扫描。
- 第 7 个及之后仍进入“其他”，避免常用区重新膨胀。

### 排序来源

常用项不保存在前端配置、YAML 或人工排序字段中，而是从数据库的真实流水生成每日快照：

1. 账户优先级统计窗口为最近 45 天，包含当天；其中最近 14 天有流水的账户属于高优先级层。
2. 高优先级层排在仅于第 15-45 天有流水的账户之前；同一层内先按该层使用笔数降序，再按最近使用日期降序。
3. 45 天内没有流水的账户不进入常用区，仍可在“其他”中选择。
4. 支出和收入分类仍统计最近 90 天，先按使用笔数降序，再按最近使用日期降序。
5. 使用笔数和最近使用日期都相同，才沿用接口的稳定顺序。
6. 每个上海日期只生成一次快照；后端启动时优先生成，若服务跨日未重启则由当天首次读取补生成。
7. 当天新录入、修改或删除流水不会覆盖已有快照，次日才会参与新的常用项排序。

账户按控件语义分别计算，避免把“经常收工资的账户”错误地放在支出支付账户首位：

| 控件 | 统计的真实流水 |
| --- | --- |
| 支付账户 | 支出流水的来源账户 |
| 到账账户 | 入账流水的去向账户 |
| 转出账户 | 转账、换汇、券商出金/入金流水的来源账户 |
| 转入账户 | 转账、换汇、券商出金/入金流水的去向账户 |
| 账户明细、流水查询、历史流水编辑 | 全部涉及该账户的流水 |

支出分类与收入分类分别按同类型流水统计。首页原有“八达通作为支出默认账户”的快捷录入规则保持不变，但它不参与常用项排序。

账户明细页首次打开时，默认选择账户优先级最高的启用账户，而不是按名称、币种或数据库编号选择。

### 前端组件行为

新增两个通用组件：

- `FrequentAccountPicker`
- `FrequentCategoryPicker`

组件接收：

- 全部可选记录。
- 当前选中 ID。
- 是否允许“全部账户 / 全部分类”空值。
- 每个页面的可选范围，例如投资页只接收投资账户。

组件输出一个真实的选中 ID，供既有 API 请求和表单提交使用；不改变后端的账户、分类参数格式。

#### 账户选择器适用位置

| 页面 | 控件 |
| --- | --- |
| 首页 | 支付账户、转出账户、转入账户、到账账户 |
| 第三页 | 账户明细账户、流水查询账户范围、修改流水的来源/去向账户、余额调整与期初修正账户 |
| 第四页 | 仅在投资账户超过 6 个时启用；当前投资账户较少时保留原生下拉框 |

对于第三页编辑历史流水：

- 已停用但被历史流水引用的账户仍必须可选择和显示。
- 这类账户只有近 90 天存在对应流水时才会进入常用区。

#### 分类选择器适用位置

| 页面 | 控件 |
| --- | --- |
| 首页 | 支出分类、收入分类 |
| 第三页 | 流水修改分类 |
| 第三页查询 | 现有多选分类保留 `details` 容器；内部按“常用 / 其他”分组，不替换为单选组件 |

流水类型只有 7 项，继续全部显示，不做常用 / 其他折叠。它们用于决定页面统计口径，隐藏后反而降低可发现性。

### 交互与可访问性

分层选择器使用按钮触发菜单，菜单内使用可点击选项，不使用文本链接伪装控件：

- 打开后焦点进入当前选中项或首个常用项。
- `Escape` 关闭菜单并回到触发按钮。
- 点击页面其他区域关闭菜单。
- 触发器使用 `aria-expanded`，菜单使用明确标签。
- 键盘上下键、`Enter`、空格可浏览和确认选项。
- “其他账户 / 分类”展开状态只影响当前打开菜单；关闭后下次重新回到常用项优先的紧凑状态。

## API 与实现影响

### 不需要修改

以下接口的请求参数不需要变化：

- `POST /api/expenses`
- `POST /api/incomes`
- `POST /api/transfers`
- `GET /api/transactions/search`
- `GET /api/transactions/analysis`
- 投资与汇率相关接口

选择器最终仍提交已有 `account_id` 或 `category_id`。

### 需要修改

1. `/api/accounts` 返回最近 45 天的账户活动数据，按账户角色分别提供总笔数、最近 14 天笔数与最近使用日。
2. `/api/categories` 返回对应收入或支出分类的最近 90 天活动数据。
3. 前端按活动数据生成常用区，不因账户名称、币种、账户编号或人工排序改变结果。
4. 流水详情分析接口的分类分布记录新增 `amount_share`。
5. 分类分布前端使用专用表格渲染，避免影响账户分布和调整方向分布。
6. 第二、三、四页长明细改为语义化折叠容器；月度投资统计改为首次展开时懒加载。

## 验收标准

### 折叠

1. 第二页“账户内资金流动”汇总卡片始终可见，明细表默认折叠。
2. 第二页“最近流水”仍始终显示最近 20 笔。
3. 第三页查询结果每页最多 20 笔，默认折叠；翻页后保持展开状态。
4. 第三页查询汇总的“全部类型合计”可见，“按流水类型”默认折叠；只选择一种类型时不显示重复的类型明细。
5. 第四页月度投资统计默认折叠，首次展开才请求数据。
6. 第四页每日汇率位于页面末尾并默认折叠；同步与手工覆盖功能展开后可正常使用。

### 分类占比

1. 分类分布显示金额、金额占比、笔数。
2. 分类金额占比以成功换算后的 HKD 总金额为分母，包含“未分类”。
3. 数值列和表头右对齐；比例保留 1 位小数。
4. 单一分类也显示表格及 `100.0%` 占比。

### 常用选择器

1. 常用账户来自近 45 天的真实流水；近 14 天使用过的账户优先，最多显示 6 项。
2. 常用分类仅来自近 90 天的真实流水，最多显示 6 项。
3. 点击“其他”后可选择全部剩余记录。
4. 已选的非常用记录不会丢失，并能在触发器显示。
5. 账户明细页首次打开时自动选择优先级最高的启用账户。
6. 首页、第三页、第四页的账户选择行为和现有表单校验保持正确。
7. 没有近期流水的初始账户不会被按名称或编号自动放进常用区。
8. 已停用的历史账户和分类在编辑旧流水时仍可显示和保存。

## 测试计划

1. API 测试：
   - 账户按来源、去向与全部流水分别返回最近 90 天活动数据。
   - 分类返回最近 90 天同类型流水的活动数据。
   - 分类分布的 `amount_share` 对多个分类、未分类和单一分类均正确。
3. 前端测试：
   - 常用项不超过 6 个。
   - 展开“其他”后可选到低频账户和分类。
   - 已选低频项重新打开、编辑、保存后不丢失。
   - 查询结果的折叠、翻页、刷新行为正确。
   - 月度投资统计仅在首次展开或提交查询时请求接口。
4. 回归测试：
   - 记账、转账、换汇、流水编辑、账户调整、投资估值、汇率同步和 Excel 导出保持正常。

## 实施顺序

1. 为账户与分类接口增加最近 90 天活动数据。
2. 实现基于活动数据的常用账户 / 分类选择器，并替换首页和第三页的相关控件。
3. 增加折叠容器、查询结果 20 条分页和月度投资统计懒加载。
4. 为流水详情分类分布增加金额占比与数值列对齐。
5. 更新使用说明、数据库手工维护说明和测试。

# 数据纠错与余额调整设计

## 目标与范围

前端已补齐日常数据纠错能力，使录错后不必直接编辑 SQLite 数据库，同时保持可追溯、可恢复，并避免用“调整余额”掩盖本来应修正的流水。

本设计包含：

- 修改已有流水。
- 删除重复或错误流水。
- 每次修改、删除、余额调整或期初余额修正前自动创建 SQLite 备份。
- 通过“调整余额”解决无法逐笔还原的账实差异。
- 修正期初余额录错或漏填。
- 在账户明细中显示手工调整、待核实异常和账实差异。

本阶段不做多人审批、权限控制、软删除恢复界面或导入银行账单自动匹配。

## 核心原则

1. 优先修正真实业务流水，而不是新增一笔调整覆盖错误。
2. 删除采用硬删除：被删除的流水不再参与余额、概况和 Excel 计算。
3. 删除前必须备份，并保存删除前快照到审计记录；不使用软删除，避免所有余额查询、导出和统计都需额外过滤。
4. 调整流水只处理无法拆回具体业务的差额，不计收入、支出、预算或当月结余。
5. 期初余额只表示建账日的真实起点；它录错时单独修正，不伪造一笔调整流水。
6. 所有纠错写操作先创建独立数据库备份，再在同一 SQLite 事务中写入业务数据和审计记录；任一步失败则不提交数据库写入。
7. 直接用 SQLite 工具或 AI 修改数据库仍然允许，但不会自动留下前端审计记录；需要可追溯时应使用前端纠错功能。

## 纠错决策表

| 发现的问题 | 正确处理 | 不应采用的处理 |
| --- | --- | --- |
| 日期、金额、账户、分类、对象或备注录错 | 修改原流水 | 再记一笔相反金额抵消，除非原流水已无法确认 |
| 同一笔消费、收入或转账重复记账 | 删除重复那一笔 | 用余额调整抵消重复金额 |
| 漏记且能知道真实业务内容 | 补录真实支出、入账、转账或换汇 | 直接调整余额 |
| 只知道银行实际余额，不知道历史差额由哪几笔构成 | 按实际差额新增调整流水 | 修改任意一笔历史消费凑余额 |
| 建账日初始金额写错或漏填 | 修正账户期初余额 | 在很久之后新增调整流水伪装为期初余额 |
| 某笔可疑但尚未确认是否错误 | 标记“待核实” | 立即删除或随意修改 |

## 数据模型

现有 `transactions` 已支持 `adjustment` 类型，无须创建新的余额流水表。新增以下两张辅助表。

### change_audit_logs

记录通过前端执行的关键纠错操作。它不是账本流水，不参与余额计算。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `entity_type` | `transaction`、`account`、`transaction_flag` 或 `reconciliation` |
| `entity_id` | 原对象编号；删除后可保留，不建立外键 |
| `action` | `create`、`update`、`delete`、`flag`、`unflag` 或 `reconcile` |
| `reason` | 用户填写的纠错原因；删除、余额调整和期初余额修正必须填写 |
| `before_json` | 修改或删除前的完整对象快照；创建时为空 |
| `after_json` | 创建或修改后的完整对象快照；删除时为空 |
| `backup_file` | 操作前自动生成的备份文件名 |
| `created_at` | 操作时间 |

`before_json` 和 `after_json` 使用 JSON 文本保存。个人项目不需要建立复杂的逐字段审计表；完整快照足以追溯和在必要时人工恢复。

### transaction_flags

用于标记“这笔流水需要进一步核实”，不会改变余额或统计。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `transaction_id` | 被标记的流水，唯一外键，删除流水时级联删除 |
| `flag_type` | `suspected_duplicate`、`missing_information`、`suspicious_amount` 或 `other` |
| `note` | 必填说明，例如“疑似与 2026-09-03 的八达通消费重复” |
| `created_at`、`updated_at` | 标记创建和最后修改时间 |

一个流水最多有一个未解决标记。解除标记时删除该记录，并写入 `change_audit_logs`。

### 既有 account_reconciliations 的用途

`account_reconciliations` 继续保存某账户某日的实际余额。它用于比较账面余额与实际余额：

```text
账实差异 = 实际余额 - 该日收盘账面余额
```

账户详情页应显示最近一次对账状态：

- `已对齐`：差异为 0。
- `存在差异`：差异不为 0，显示金额与对账日期。
- `待对账`：没有对账记录。

完成余额调整后，系统应同时写入或更新该日期的对账记录，使其成为“已对齐”的依据。

## 修改流水

### 允许修改的字段

修改页复用记账页的三种表单规则，可修改：

- 日期。
- 交易类型。
- 来源和去向账户。
- 转出与转入金额。
- 收入或支出分类。
- 对象和备注。

交易类型变化时必须重新满足数据库的既有约束：

- 收入：仅有去向账户、流入金额和收入分类。
- 支出：仅有来源账户、流出金额和支出分类。
- 转账或换汇：同时有来源和去向账户，且没有分类。
- 调整：仅允许单边来源或去向账户，且没有分类。

后端不能直接相信前端提交的数据，应复用新增流水时的账户、币种、分类和金额校验。编辑历史流水时，可以保留原本已停用的账户或分类；但不能把流水改到一个新的已停用账户或分类。

### 修改流程

1. 在账户明细或流水查询结果中点击一笔流水的编辑操作。
2. 前端打开与记账类型对应的编辑表单，并展示该笔原始数据。
3. 用户修改并提交；若影响账户、金额、类型或日期，确认框提示会影响余额、月度概况和 Excel。
4. 后端创建备份，读取旧记录，执行校验和更新，写入审计日志。
5. 前端刷新当前筛选结果和相关账户摘要。

修改保留原 `transactions.id`；`updated_at` 更新，审计日志记录前后快照。

## 删除流水

删除用于处理确认无效、重复或错误且不应保留的流水。

### 删除流程

1. 结果行提供删除操作。
2. 对话框显示日期、类型、账户路径、金额和当前余额影响。
3. 用户必须填写删除原因，例如“与银行账单重复导入”。
4. 用户二次确认后，后端先创建备份。
5. 后端读取完整流水及其异常标记快照，删除流水，写入删除审计记录。
6. 前端刷新当前列表、账户余额、概况和 Excel 数据源。

删除不是撤销按钮。恢复应通过：

- 从操作前备份恢复整个数据库；或
- 依据 `change_audit_logs.before_json` 手工补回被删除流水。

后续可以增加“从审计快照恢复单笔流水”，但不属于本次实现。

## 余额调整

### 使用场景

余额调整只适用于以下情况：

- 已核对实际余额，但缺少的历史流水无法可靠拆分。
- 历史导入不完整，知道总差额但不知道每笔业务。
- 投资市值变化等不属于收入、支出或转账的资产变动。

调整表单字段：

- 账户。
- 调整日期，默认今天。
- 账面余额，只读显示。
- 实际余额，用户填写。
- 差异，前端预览。
- 必填调整原因。
- 可选补充备注。

系统根据“实际余额 - 账面余额”自动决定单边方向；用户不手工选择流入或流出，避免资产/负债方向填反。

### 调整算法

先计算所选账户在调整日期收盘时的账面余额。

资产账户：

```text
差异 = 实际余额 - 账面余额
差异 > 0：写入 adjustment 流入
差异 < 0：写入 adjustment 流出
```

负债账户：

```text
差异 = 实际负债余额 - 账面负债余额
差异 > 0：写入 adjustment 流出，增加负债
差异 < 0：写入 adjustment 流入，减少负债
```

调整金额为差异绝对值。若差异为 0，不创建流水，只写入或更新对账记录。

调整日期默认今天。若选择的日期早于该账户最后一笔流水，前端必须警告：该调整会重算后续所有余额和历史净资产；仍允许确认，因为有时需要回填历史对账日。

调整流水规则：

- `transaction_type = 'adjustment'`。
- 没有收入/支出分类，不进入月度收入、支出、预算和结余。
- `note` 以用户填写的调整原因开头，确保在数据库和 Excel 中可读。
- 明细页以“手工调整”徽标突出显示。
- 写入前备份，写入后建立或更新对应日期的 `account_reconciliations`。

## 修正期初余额

期初余额表示 `opening_balance_date` 当天建账前的真实余额。漏填或录错时应通过独立“修正期初余额”操作修改 `accounts.opening_balance_minor`，而不是创建当日调整流水。

表单字段：

- 账户。
- 期初日期。
- 新期初余额。
- 必填修正原因。

操作前端要求确认，提示该账户所有后续账面余额都会重算。后端创建备份，更新账户，写入 `change_audit_logs`。

不允许用该功能处理已经明确属于后续某笔业务的错误；那种情况应修改、删除或补录对应流水。

## 账户明细与流水查询的展示

### 账户明细

账户摘要增加：

- 最近对账日期、实际余额、账面余额和账实差异。
- 对账状态：已对齐、存在差异或待对账。
- “调整余额”操作。
- “修正期初余额”操作。

流水行增加状态列和操作列：

- `手工调整`：`transaction_type = adjustment`。
- `待核实`：存在 `transaction_flags`。
- `已对齐参考`：可选显示与最近对账日相同的流水日期，不作为独立数据状态。
- 操作：编辑、删除、标记待核实或解除标记。

筛选增加：

- 仅看手工调整。
- 仅看待核实流水。
- 仅看与账实差异相关的账户。

### 流水查询

跨账户流水查询保留现有日期、账户、多个类型、多个分类和关键词筛选，并增加：

- 仅手工调整。
- 仅待核实。
- 行内编辑、删除和标记待核实操作。

删除或修改转账、换汇时，查询结果必须把两端账户和两种金额都展示在确认框中。

## 建议 API

### 流水读写

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/transactions/{transaction_id}` | 获取单笔流水，供编辑表单预填 |
| `PUT` | `/api/transactions/{transaction_id}` | 修改一笔流水 |
| `DELETE` | `/api/transactions/{transaction_id}` | 删除流水；请求体必须包含 `reason` |
| `POST` | `/api/accounts/{account_id}/adjustments` | 根据实际余额创建调整流水和对账记录 |
| `PUT` | `/api/accounts/{account_id}/opening-balance` | 修正期初余额；请求体必须包含 `reason` |

### 异常与对账

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `PUT` | `/api/transactions/{transaction_id}/flag` | 新增或更新待核实标记 |
| `DELETE` | `/api/transactions/{transaction_id}/flag` | 解除待核实标记 |
| `POST` | `/api/accounts/{account_id}/reconciliations` | 记录实际余额并返回账实差异 |
| `GET` | `/api/accounts/{account_id}/reconciliations` | 查看历史对账记录 |

现有账户详情和流水查询接口应增加以下只读字段：

- `is_manual_adjustment`
- `flag`：为空或包含 `flag_type`、`note`、时间
- `reconciliation_status`：账户摘要字段

## 数据库迁移与兼容性

当前初始化逻辑只执行 `CREATE TABLE IF NOT EXISTS`，不会自动给既有表补列。此次新增两张表不需要修改已有 `transactions` 字段，因此可通过 `schema.sql` 增加表、索引与触发器，再由 `initialize_database()` 自动创建。

建议约束：

- `transaction_flags.transaction_id` 使用 `UNIQUE` 和 `ON DELETE CASCADE`。
- `transaction_flags.flag_type` 使用固定枚举检查。
- `change_audit_logs.entity_id` 不建立外键，以保存已删除对象的编号。
- 对账记录的唯一约束继续使用现有 `(account_id, reconciliation_date)`。

## 实施顺序

1. 新增 `change_audit_logs` 与 `transaction_flags`，并为它们写查询辅助函数。
2. 抽取新增流水的公共校验和金额转换逻辑，为新增和修改共用。
3. 实现读取单笔、修改和删除流水 API；所有写操作都调用 `create_backup()`。
4. 实现余额调整、期初余额修正与对账 API。
5. 在“账户与流水”页增加行内操作、调整余额、期初修正、异常标记和对账状态。
6. 后续可扩展 Excel：交易流水显示“手工调整 / 待核实”状态，或增加“纠错与对账记录”工作表。
7. 增加隔离测试：资产/负债调整方向、删除转账两端余额、修改类型与分类校验、备份创建、审计快照、异常标记和对账差异。

## 验收标准

- 修改一笔支出、收入、转账或换汇后，所有受影响账户余额正确重算。
- 删除任何流水前创建独立备份，删除后记录可从审计日志追溯。
- 重复流水可以删除，不会留下余额影响。
- 调整实际余额时，资产和负债的方向均正确，且不影响收入、支出、预算和当月结余。
- 期初余额修正后，账户全历史余额一致重算。
- 账户详情能显著显示手工调整、待核实流水和最近账实差异。
- 所有纠错 API 在失败时不改变主数据库。

## 冲销事项扩展（2026-09-29）

原始流水口径继续遵循本文。新增的“冲销后收支”基于完整事项计算净额，再按事项日期、方向和分类筛选，关联成员不重复计入；跨账户筛选使用“涉及账户”语义。负数、跨月、汇率缺失和关联流水编辑 / 删除规则见 [transaction-offset-design.md](transaction-offset-design.md)。

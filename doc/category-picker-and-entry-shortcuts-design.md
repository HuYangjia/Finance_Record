# 分类滚动选择与首页便捷操作设计

设计日期：2026-10-18。状态：已实现。

## 背景与结论

首页及流水编辑中的支出、收入分类目前使用“常用分类 / 其他分类”两层选择器。常用项按近期使用频率排列，剩余项需要再次展开并按固定业务顺序显示。这既增加一次点击，也让同一面板出现两种排序口径。

首页左侧三个便捷操作目前写死在 HTML 和 JavaScript 中，用户不能新增、修改、停用或排序；设置页的“收入 / 支出预设”只服务预算预填，也不能表达转账或换汇。

本轮确认以下方向：

1. 支出和收入分类不再区分“常用 / 其他”，全部放在同一个固定高度列表中排序，超过可见行数后滚动。
2. 分类使用与账户相同的长短窗口加权算法，支出、收入分别计算。
3. 首页便捷操作改为数据库配置，在设置页以卡片列表和弹窗编辑；统一支持支出、入账、转账 / 换汇。
4. 两项功能都只改变选择和预填，不改变真实流水、账户余额、预算统计或冲销口径。

## 一、分类选择器

### 1. 排序规则

支出分类只统计支出流水，收入分类只统计收入流水。每个分类计算：

```text
排序分数 = 最近 45 天笔数 + 最近 14 天笔数 × 5
```

最近 14 天包含在最近 45 天内，因此最近 14 天的一笔记录得到 6 分，第 15 至 45 天的一笔记录得到 1 分。排序依次比较：

1. 排序分数降序。
2. 最近 14 天笔数降序。
3. 最近 45 天笔数降序。
4. 最近使用日期降序。
5. 分类原有 `sort_order`、完整显示名称和 ID，保证完全相同时仍稳定。

45 天内没有流水的分类统一排在有使用记录的分类之后，并按原有业务顺序排列。父子分类只统计实际被流水引用的末级分类，显示名称继续使用“父分类 / 子分类”。

排序使用上海日期的每日快照：同一天内顺序保持稳定，第二天首次读取分类时纳入前一天的新流水。修改、删除或重新分类的流水也在下一份快照中反映，不要求每保存一笔就让正在操作的菜单跳动。

### 2. 展示与操作

分类菜单使用一个连续列表，不显示“常用分类”“其他分类”和二次展开按钮：

- 最多同时显示 8 行分类；不足 8 行时按实际数量收缩。
- 超过 8 行后，菜单高度不再增加，鼠标滚轮、滚动条和键盘上下键访问后续项目。
- 打开菜单时，当前选中项自动滚入可见区域并保持高亮。
- `Enter` 或空格确认，`Escape` 关闭并把焦点还给触发按钮。
- 选中结果仍写回原生 `select`，沿用现有表单校验和 API 参数。
- 首版不增加搜索框；当前支出 13 类、收入 7 类，8 行视窗已足够。分类明显增长后可再增加搜索，不需要改变排序接口。

首页支出默认分类仍为“餐饮”，排序只决定菜单中的位置，不擅自改变默认选择。编辑历史流水时，已停用但正在被该流水引用的分类仍可显示；列表名称附“已停用”，不能用于新流水。

### 3. 适用范围

统一滚动排序应用于单选分类控件：

- 首页支出分类、收入分类。
- 第三页修改历史流水的分类。
- 设置页分类映射、收入 / 支出预设的分类。
- 新增的首页便捷操作弹窗中的支出、收入分类。

第三页查询中的分类多选保留现有完整业务顺序和多选容器。查询常常需要同时勾选多个概念，动态频率排序会降低批量筛选的稳定性。

账户数量更多且承担支付、到账、转出、转入等不同角色，继续使用角色相关的优先级；后续已将低频入口升级为包含全部账户的业务目录，详见 [账户选择器全量目录设计](account-picker-directory-design.md)。

### 4. 快照与接口调整

`daily_category_frequent_activity` 增加：

- `recent_record_count`：最近 14 天笔数，非负整数，默认 0。

现有 `record_count` 改为最近 45 天笔数，`last_transaction_date` 保存该 45 天窗口内最近使用日期。`GET /api/categories` 的 `activity.usage` 返回三项数据，与账户活动对象结构一致：

```json
{
  "record_count": 12,
  "recent_record_count": 8,
  "last_transaction_date": "2026-10-17"
}
```

实现时提高 `FREQUENT_SNAPSHOT_RULE_VERSION`。如果当天已经存在旧规则快照，初始化会删除并重建当天派生快照；历史流水及分类本身不修改。迁移前仍创建账本备份，随后检查外键和数据库完整性。

前端复用活动分数比较函数，但为分类启用 `ranked-scroll` 展示模式；账户继续使用 `common-other` 模式。零使用分类不能被过滤掉，只在有记录分类之后使用接口原始顺序。

## 二、首页便捷操作

### 1. 与现有预设的边界

设置中的“收入 / 支出预设”继续负责在表单内选择一组分类、预算和可选账户，尤其用于区分不同工资来源。它不承担首页左侧展示，也不支持资金移动。

新增“首页便捷操作”作为独立设置：

- 便捷操作决定首页左侧显示什么按钮以及点击后预填哪些字段。
- 它可以使用自动预算规则，也可以固定一个预算归属。
- 它不创建、修改或删除“收入 / 支出预设”，两者可以并存。
- 点击便捷操作只准备表单，不直接保存流水。

### 2. 数据模型

新增 `transaction_entry_shortcuts`：

| 字段 | 含义 |
| --- | --- |
| `id` | 主键 |
| `name` | 首页按钮名称，不能为空且唯一 |
| `mode` | `expense`、`income` 或 `transfer` |
| `source_account_id` | 支付或转出账户，可空外键 |
| `destination_account_id` | 到账或转入账户，可空外键 |
| `category_id` | 支出或收入分类，可空外键 |
| `budget_system_id` | 明确预算归属；空值表示应用当前自动规则 |
| `outflow_minor` | 可选支付 / 转出金额，按来源账户币种最小单位保存 |
| `inflow_minor` | 可选到账 / 转入金额，按去向账户币种最小单位保存 |
| `counterparty` | 可选商户、来源或对象 |
| `note` | 可选备注 |
| `sort_order` | 首页及设置卡片顺序 |
| `is_active` | 是否在首页显示 |
| `created_at`、`updated_at` | 创建和更新时间 |

金额只是表单模板，不参与余额和统计。弹窗按所选账户币种显示十进制金额，保存时再编码为最小单位；更换账户后，当前输入数字按新账户币种精度重新校验，不进行汇率换算。

按模式校验：

- 支出：必须选择启用的来源账户和启用的支出末级分类；去向账户、转入金额为空。预算可以留空自动处理。
- 入账：必须选择启用的去向账户和启用的收入末级分类；来源账户、转出金额为空。预算可以留空自动处理。
- 转账 / 换汇：必须选择两个不同且启用的账户；分类和预算为空。转出金额可留空；同币种且已填转出金额时，转入金额自动相同；跨币种的转入金额可留给实际记账时填写。
- 预填金额如果存在必须大于 0，并符合对应币种精度。

账户、分类和预算均使用稳定 ID，不用名称或账户编号在每次点击时重新猜测。被引用对象后来停用时保留便捷操作，但首页按钮禁用并显示原因；设置卡片标记“需要修复”。删除被引用的基础对象仍沿用现有外键限制。

### 3. API、并发与审计

新增独立接口：

- `GET /api/entry-shortcuts`：返回配置版本、按 `sort_order, id` 排列的全部便捷操作及引用对象摘要。
- `POST /api/entry-shortcuts`：新增。
- `PUT /api/entry-shortcuts/{id}`：修改、启停。
- `PUT /api/entry-shortcuts/order`：一次保存完整顺序。
- `DELETE /api/entry-shortcuts/{id}`：删除未产生业务引用的模板。

`app_settings.entry_shortcut_version` 保存乐观并发版本。所有写接口提交 `expected_version`，版本不符返回冲突并要求重新加载，避免两个设置页互相覆盖。

每次新增、修改、排序或删除前创建数据库备份，并在 `change_audit_logs` 中使用新的 `entry_shortcut` 实体记录前后快照和备份文件。审计约束迁移需保留所有已有实体与记录。便捷操作不是流水，不进入 Excel 财务导出。

### 4. 既有按钮迁移

首次创建新表前生成 `finance-pre-entry-shortcuts-*.db`。一次性迁移把当前三个硬编码操作写成配置：

1. 八达通餐饮：支出，学生八达通，餐饮分类，金额留空，预算自动。
2. 微信转八达通：转账，微信零钱到学生八达通，金额留空。
3. 支付宝定投 35：转账，支付宝余额到支付宝基金，转出金额 35 CNY，备注“每日定投”。

迁移按稳定账户 ID 和分类 ID 保存结果；编号和名称只用于首次查找。测试账本缺少对应基础对象时跳过相应种子项，不创建悬挂引用。迁移状态由表是否首次创建或单独的迁移标记判断，用户日后删空列表时不得自动恢复三个默认按钮。

迁移完成后删除 HTML 和 JavaScript 中的硬编码按钮及对象。旧按钮的点击行为、预算自动解析和“仍需手动保存”规则保持一致。

### 5. 设置页交互

设置页增加独立的“首页便捷操作”区域，不混入预算栏目下拉列表：

- 卡片始终显示名称、模式和主要预填摘要。
- 启用状态、引用失效警告和首页顺序可直接看见。
- 提供上移、下移、编辑、启停和删除；排序不能只依赖拖拽，保证键盘操作可用。
- 鼠标悬停或键盘聚焦时可突出操作按钮，但编辑入口不能只在悬停时存在。
- “新增”及“编辑”使用居中的原生 `dialog` 弹窗卡片，标题和保存区固定，内容区滚动。
- 模式切换后只显示该模式可用字段；保存成功关闭弹窗，校验失败保留输入并在字段旁显示原因。
- 弹窗底部实时展示将出现在首页的按钮名称及预填摘要。

本轮只以电脑浏览器为验收目标，保留现有手机样式但不新增手机布局。

### 6. 首页交互

首页加载时读取启用便捷操作并按设置顺序生成按钮。左栏最多直接显示约 8 个按钮的高度，更多按钮在该区域内部滚动，不拉长整个记账页面。

点击按钮时：

1. 切换到对应记账模式。
2. 如果该模式已有未保存输入，先确认是否用便捷操作替换这份草稿；其他模式草稿不受影响。
3. 重置目标模式到正常默认值，再覆盖便捷操作明确配置的账户、分类、金额、对象和备注。
4. 预算为空时按“分类映射 → 模式默认”重新解析；设置了预算时视为本笔明确选择。
5. 日期使用点击当天，不把日期保存进模板。
6. 聚焦第一个仍为空的必填字段，通常是金额；所有字段齐全时仍不自动提交。

按钮引用失效时保持可见但禁用，悬停说明缺少或停用的对象，并提供前往设置修复的入口。读取便捷操作失败不阻断普通记账表单。

## 三、兼容性与验证

### 不改变的内容

- `transactions` 表及真实流水金额。
- 支出、收入、转账和换汇 API 的请求语义。
- 账户余额、预算执行、冲销事项、投资估值和 Excel 统计。
- 账户选择器的“常用 / 其他”分层规则。
- 第三页查询分类多选的稳定业务顺序。

### 验收标准

1. 支出和收入单选分类菜单不存在“其他分类”入口，最多显示 8 行并可滚动到底。
2. 分类按与账户相同的 `45 天笔数 + 14 天笔数 × 5` 规则排序，收入与支出互不混合。
3. 零使用分类不丢失；当前选中分类打开时可见；历史停用分类仍能显示。
4. 设置页可新增、修改、启停、排序和删除三种模式的便捷操作。
5. 现有三个首页按钮迁移后预填结果与当前一致，且不会重复创建。
6. 新增的支出便捷操作能够预填账户、分类、可选预算、金额、对象和备注。
7. 点击任何便捷操作都不会直接产生流水；保存后继续走现有后端校验并显示账户余额。
8. 停用被引用的账户、分类或预算后，按钮明确禁用且普通记账仍可用。
9. 设置写入有备份、审计和版本冲突保护；数据库外键检查和完整性检查通过。
10. 后端分类排序、便捷操作校验和迁移使用隔离账本测试；电脑浏览器覆盖滚动选择、弹窗编辑、排序和三种模式预填。

## 四、实现结果

1. 分类每日快照已升级到规则版本 3，增加最近 14 天笔数；原 `record_count` 使用 45 天窗口。支出和收入单选分类均使用连续排序、8 行视窗和滚动，账户选择器保持原分组方式。
2. 已增加 `transaction_entry_shortcuts`、配置版本、迁移种子、备份、审计和 CRUD / 排序接口。
3. 设置页已提供卡片列表和弹窗，支持新增、修改、启停、上移、下移和删除；首页从接口生成按钮。
4. 原有三个按钮首次升级时按现有账户和分类迁移；标记保证用户以后删空列表也不会再次生成。
5. 自动化验证覆盖排序窗口、迁移幂等、三种模板校验、并发版本、审计和备份；浏览器脚本覆盖设置弹窗、滚动菜单及首页预填。

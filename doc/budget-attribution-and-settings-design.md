# 预算归属、默认映射与首页模式设计

设计日期：2026-10-01。状态：首版已实现；遵循先文档后代码。正式账本在下次启动时自动备份并升级。

## 2026-10-01 调整：日常消费免标注

按用户确认，所有未单独指定预算的**支出**（包括历史记录）在明细、查询汇总、图表和冲销统计中自动归入日常预算。只需手选少量非日常预算。已有明确预算标记优先；收入继续保留独立归属规则，转账、换汇和余额调整不自动当作日常消费。

保留原流水的可空 `budget_system_id`，查询另提供 `effective_budget_system_id/name` 与 `budget_inherited`；不批量回填历史流水。编辑中选择“日常预算（自动）”表示清除单独标记，统计仍计入日常。查询“未归属”不再包含这些支出。

设置新增稳定的 `daily_expense_budget_system_id`，单独指定哪套预算承接未标注支出，与“新增支出预填预算”区分。首次升级优先使用已有启用的“日常预算”，否则沿用已配置的支出默认预算；没有可用预算时创建日常预算。之后改名和改变新增预填项不会悄悄迁移历史统计。更换日常归属会将所有未单独标注的支出一起切换；界面明确说明其影响。正在承接日常归属的预算不能停用或删除。

冲销事项按主方向成员的**有效归属**判断：未标注支出与明确日常支出可以共同归入日常；未标注支出与专项支出仍视为跨预算事项。先计算完整事项净额，再进行预算筛选。

界面调整保持现有控件和数据操作：统一留白、颜色、字号、导航和卡片；预算选择、统计数字、保存按钮突出；栏目管理分组呈现；表格横向滚动限定在表格容器。桌面与手机均验证下拉选项、独立草稿、保存、历史版本及统计筛选。

## 1. 目标与关系

用户有两份工资，准备分别用于日常和其他安排；希望记账时标注这笔消费属于哪套预算，在已有第三页直接筛选。学费、杂费、给他人的酬劳可以单独归属，日常消费保持快速录入。默认预算及映射由用户在设置页维护。

第六页仍保存手工预算计划，规则见 [多预算计划设计](budget-and-fund-allocation-design.md)。新增的是实际流水的“预算归属”维度，不自动扣减计划，也不证明某笔消费物理上使用了某一次工资到账的钱。

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| 真实账户 | 钱从哪里付、收进哪里 | 银行卡、八达通 |
| 流水分类 | 实际发生了什么业务 | 餐饮、学费、工资/劳务支出 |
| 预算系统 | 这笔收支统计在哪套安排下 | 日常预算、专项预算 |
| 预算用途与存储方式 | 该系统中如何提前安排计划 | 留存 × 定期、慈善 × ETF |

同一支付账户可以支付日常与专项消费；同一支出分类也可以在不同预算下使用。因此预算系统既不等于账户，也不等于流水分类。

后续新增需求采用简化方案：每份月度预案可绑定一个净收入来源，以预案总额占用额度，同一来源下所有已绑定预案的合计不得超过净收入，见 [预案绑定收入来源与额度校验](budget-and-fund-allocation-design.md#预案绑定收入来源与额度校验当前设计)。这与本页的单一流水标签不同，不需要另填金额或比例，也不拆分、复制原始收入。绑定不会将来源全额再次加入预算，既有第三页标签筛选不变。目前只完成设计，尚未实现。

## 2. 多预算系统与实际归属

预算系统可自定义名称，例如：

- 日常预算：工资 B 的日常安排，餐饮、交通等默认归入。
- 专项预算：工资 A 的安排，学费、杂费、劳务支出等可映射到这里。

“专项预算”只是示例名称，用户可以拆成更多系统，不写死“系统 1 / 系统 2”或哪份工资金额较大。未编制当月计划也能标记流水归属；历史消费查询不依赖该月必须先有预算金额。

建议第一版一笔收入或支出选择一个预算系统。先满足快速归类与统计，不自动将一笔金额拆给多个系统。确实需要跨预算分摊时，再增加受总额校验的分摊明细，不能简单把整笔金额复制到两个系统。

真实支出只需多选一个“预算归属”。不强制再选计划中的存储方式、用途或某条月预算明细，避免日常记账增加过多步骤。

学费、杂费、劳务支出仍是各自的真实支出分类；预算归属负责将它们与日常消费区分。备注可以写收款人、项目，但不靠备注关键词充当唯一筛选依据。支付别人的工资使用支出；本人收到工资使用入账。

## 3. 独立设置页

2026-10-18 已完成“首页便捷操作”扩展设计，等待实现。它将在设置页作为独立卡片区管理，可通过弹窗新增和编辑支出、入账、转账 / 换汇按钮；现有 `budget_entry_presets` 继续负责表单内的预算预填，不与首页按钮混为同一对象。详见 [分类滚动选择与首页便捷操作设计](category-picker-and-entry-shortcuts-design.md)。

建议增加导航入口“设置”，路径 `/settings`。设置不是另一套预算；预算编辑仍在第六页。设置页分组管理：

| 分组 | 可操作内容 |
| --- | --- |
| 预算系统 | 新建、改名、排序、停用；查看被计划或流水引用的情况 |
| 默认项 | 支出默认预算、入账默认预算，分别选择 |
| 分类映射 | 为指定收入 / 支出末级分类设置默认预算 |
| 收入与记账预设 | 工资 A、工资 B 等命名预设；预填分类、预算及可选账户 |
| 预算栏目 | 选择预算系统后管理用途、存储方式与层级 |

建议首次提供一个可改名的“日常预算”，将其设为新支出的默认项；用户可以选择其他启用预算作为默认。默认以稳定 ID 保存，不根据名称“日常”猜测。

入账默认可独立设置或留空，不无条件沿用支出默认。两份工资即使都用现有“工资/劳务”收入分类，也可通过“工资 A / 工资 B”两个预设选不同预算，避免为了区分工资而必须改动所有真实收入分类。

映射示例：

| 条件 | 默认预算 |
| --- | --- |
| 支出 / 餐饮 | 日常预算 |
| 支出 / 交通 | 日常预算 |
| 支出 / 学费 | 专项预算 |
| 支出 / 杂费 | 专项预算 |
| 支出 / 工资/劳务支出 | 专项预算 |
| 入账预设 / 工资 A | 专项预算 |
| 入账预设 / 工资 B | 日常预算 |

同类业务可能来自不同预算，所有预填结果均可在当次录入中修改。第一版分类映射按末级分类精确匹配，每个模式、分类至多一个启用规则；不引入模糊备注识别或金额大小猜测。

真实分类与预算用途分别管理；映射只是关联设置，不在真实分类树里复制“日常餐饮”“专项餐饮”来模拟预算系统。

## 4. 默认值与手动选择的优先级

建议从高到低：

1. 用户对当前表单明确选择的预算，包括支出的“日常预算（自动）”和收入的“未归属”。
2. 用户主动使用的命名预设中指定的预算。
3. 当前模式、分类匹配的预算映射。
4. 该模式在设置页配置的默认预算。
5. 没有可用结果时，支出自动计入日常预算，收入显示“未归属”。

表单显示预填依据，例如“默认：日常预算”“按学费分类：专项预算”，便于核对。

- 用户尚未手选预算时，改变分类可重新匹配；已经手选后，不被分类变化悄悄覆盖，提供“恢复自动选择”。
- 保存一笔专项支出后，新一笔支出重新应用当前默认 / 分类映射；不能把上一笔的专项预算无提示地带给下一笔餐饮消费。
- 编辑历史流水时，显示已保存的预算，不重新套用今天的默认规则。重新按映射归类须由用户明确操作。
- 修改预填设置只影响后续预填，不批量重写历史。未标注支出显示“日常预算 · 自动”；单独更换日常归属会改变所有未标注支出的统计归属，明确标记保持不变。
- 停用默认预算时要求同时选择替代项或明确取消默认；相关预设 / 映射须一并停用或重定向，不能留下不可见的失效引用。
- 设置读取失败时，原有记账仍可用，预算栏显示未加载提示；未标注支出仍由后端按日常预算统计，不中断账户、分类初始化。

用户选择默认日常预算，是省去每笔重复选择，不意味着第三页默认隐藏专项消费。第三页默认查询范围仍为全部预算，选择日常预算后明确显示筛选条件。

## 5. 首页三种模式的分离

首页现在采用三个独立表单，各自保存当前页面内的草稿、校验和提交，只显示当前模式。切换模式保留日期、金额、备注和预算选择；刷新页面不保存未提交草稿。为兼容既有首页结构，初始化时从原始模板拆出三个表单，保留原账户和分类选择器编号。

仍在首页用清楚的三个页签切换，不需要用户跳三个页面：

| 模式 | 主要字段 | 预算相关内容 |
| --- | --- | --- |
| 支出 | 日期、支付账户、金额、支出分类、对象、备注 | 预算归属，默认日常或分类映射 |
| 入账 | 日期、到账账户、金额、收入分类、来源、备注 | 可选收入预设、预算归属，与支出默认独立 |
| 转账 / 换汇 | 日期、转出账户、转入账户、付出金额、收到金额、备注 | 首版不要求消费预算归属 |

交互要求：

- 三个模式有独立草稿；切换后返回仍保留尚未保存的输入，保存只清理当前模式。
- 隐藏表单不参与当前提交和必填校验；不可把支出预算带进入账或转账请求。
- 支出常用操作仍可一键预填，预算按当前规则解析；工资预设只影响入账表单。
- 支出保持简洁，只增加一个预算选择；高级说明和映射管理折叠到设置入口。
- 同币种转账、跨币种换汇、信用卡还款与投资账户间转账，继续沿用原始资金移动语义，不作为预算消费再次统计。

## 6. 第三页按预算统计

### 6.1 原始流水查询

在第三页“流水查询”增加预算筛选：全部、单个预算，以及未归属；停用但有历史记录的预算仍可选。结果行显示预算名称，原始流水编辑弹窗支持改选预算。

用户的日常消费查询路径为：

```text
流水查询 → 预算归属：日常预算 → 类型：支出 → 日期范围 → 查询
```

金额汇总、分页总数、每日统计、图表和明细必须应用同一筛选；先筛选再汇总，不能只过滤当前页。账户、分类、关键词、标记筛选可与预算筛选同时使用。

只看消费必须选择支出类型；若同时选择收入，汇总明确分别列收入和支出，不能把工资到账也显示成日常消费。

计划中的存储方式不会变成筛选实际资金来源的条件：真实支出来自哪个账户，仍由账户字段决定。

账户明细可显示预算标记，但逐笔账户余额始终从完整原始流水计算。若后续增加预算筛选，也只能筛选可见行，不能把筛选后的消费合计当成真实账户余额。

### 6.2 与冲销后统计的组合

预算标记仍属于原始流水。冲销统计必须先获取完整事项、计算净额，再应用预算筛选，不能先丢掉其他预算标记的回款或分出流水。

建议事项的预算统计归属按主方向成员推导：

- 所有主方向成员属于同一个预算：完整事项归该预算，包括不同月份的冲抵成员。
- 所有主方向支出成员都未单独指定：事项归日常预算；主方向收入都未归属时，收入事项归“未归属”。
- 主方向成员的有效归属跨多个预算：列为“跨预算 / 待归属事项”，不自动将整项全额放进每一个预算。未标注支出与明确日常支出可以合并统计。

例如日常支出 600，收到归还 200，支出事项在日常预算下按净支出 400 计；回款即使因收入默认项被标为另一预算，也不会使原支出恢复成 600。

若选定预算涉及一个跨预算事项，应在查询结果外明确展示待归属事项数量及入口，合计标明尚有未分配项，不能将其悄悄排除后声称统计完整。无预算筛选时，该事项净额仍只计一次。

第一版不做自动金额分摊。需要精确分到多个预算时，用户可核对主流水标签或重新组织确实可分开的事项；不可为了凑统计而自动改写标签。该规则是实现建议，后续涉及跨预算实际场景时再细化。

## 7. 数据模型与兼容性草案

| 对象 | 建议 |
| --- | --- |
| `budget_systems` | 稳定 ID、名称、启用、排序、备注；由计划与实际流水共同引用 |
| 月计划和栏目 | 增加 `budget_system_id`，计划唯一键为系统、月份、币种；栏目独立管理 |
| `transactions.budget_system_id` | 可空外键；首版用于收入 / 支出统计归属，旧记录默认空 |
| `budget_assignment_rules` | 收入 / 支出模式、末级分类 ID、目标预算 ID、启用状态 |
| `budget_entry_presets` | 名称、模式、预算 ID、可选账户与分类，便于区分两份工资 |
| `app_settings` | 复用已有键值表，保存支出 / 入账默认预算 ID 等简单设置 |

已有 `app_settings` 可复用，但不能将栏目、规则和逐笔金额都塞进同一个设置 JSON；可查询关系使用专门表。设置中的 ID 由服务校验，关系表及流水使用外键保护。

新增预算、改名、停用、配置默认、映射和归属编辑都通过页面与后端接口完成，使用已有备份与审计约定。

兼容要求：

1. 迁移给旧流水增加可空标签，不改变金额、分类、账户、日期或原始笔数。未标注支出通过有效归属计算纳入日常，不批量回写流水。
2. 原始 API 未提供预算字段时，新增仍保存空标签，支出按日常统计；编辑未提供该字段时保留旧值，显式空值清除单独标记，支出恢复自动日常归属。
3. 新前端提交明确的预算 ID 或未归属结果，服务端校验；默认解析在前后端采用相同规则，避免页面显示日常、保存却变为专项。
4. 不选择预算筛选时，既有查询金额与余额算法不变；汇总接口和图表共用同一预算筛选参数。
5. 冲销统计使用完整事项，对预算归属的推导与第三页显示一致；不增加事项成员的重复计数。
6. 查询不因新增字段失去历史停用预算或未标注流水；新客户端和旧缓存页面混用时基础记账仍可初始化。
7. Excel 原始流水可增加预算名称列；需要导出筛选结果时明确预算范围，不把页面筛选与全账导出混为一谈。
8. 标签、默认设置和映射变化不自动修改第六页预算金额；编制或修改预算也不改实际收支标签。

## 8. 验收场景

| 场景 | 预期 |
| --- | --- |
| 新建普通支出 | 默认日常预算，用户可修改 |
| 选择映射为专项的学费分类 | 未手选预算时自动预填专项，明确依据 |
| 手动选日常，再更换分类 | 不覆盖手动选择，可恢复自动 |
| 保存专项支出后录入餐饮 | 重新应用默认，不能沿用专项造成误归类 |
| 工资 A、B 都用工资/劳务收入分类 | 分别使用收入预设即可标记不同预算 |
| 日常支出 100、专项支出 200、未标注支出 50 | 日常筛选合计 150，专项 200，全部 350；不需要逐笔补标 |
| 修改默认和映射 | 旧流水归属及原有金额不变 |
| 原始标签补标或纠正 | 预算筛选结果更新，账户余额不变，计划数不变 |
| 未编制月预算但已录入流水标签 | 第三页仍可查，该月第六页仍显示未编制 |
| 日常支出 600、回款 200 组成事项 | 日常冲销后支出 400，原始口径保留原始收付 |
| 事项主流水跨两个预算 | 单独显示待归属，不能在两个预算下重复计全额 |
| 切换首页三个模式 | 草稿独立，字段与默认值不串用，隐藏模式不阻止保存 |
| 转账、换汇或信用卡还款 | 不作为预算支出重复统计 |
| 设置组件缺失或请求失败 | 基础账户 / 分类及记账流程仍可用 |

## 9. 当前阶段

首版已实现多预算系统、逐笔预算归属、第三页筛选、默认项、精确分类映射、工资命名预设及三个独立表单。冲销事项先完整计算，再应用预算筛选；跨预算主流水不自动分摊，结果展示遗漏事项及入口。

实现位置：`app/budgets.py`、`app/budget_schema.sql`、`static/settings.*`、`static/app.js`；原始查询与编辑由 `app/main.py`、`static/accounts.*` 接入，冲销归属由 `app/personal_cashflow.py` 推导。`budget_system_id` 查询参数不传为全部、`0` 为有效归属为空（不含自动日常支出）、正整数为指定预算。创建接口未传保留空标签，编辑接口未传保留原值；有效归属在查询时计算。

设置使用全局版本号防止旧页面覆盖新设置；月计划使用各自版本号。默认预算和映射只用于首页预填，历史流水需在编辑弹窗明确修改。首次升级备份为 `finance-pre-budget-*.db`，只新增可空字段，不回填历史归属。批量补标和一笔金额跨预算分摊留待后续独立设计。

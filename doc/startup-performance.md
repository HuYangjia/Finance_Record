# 启动性能与后台汇率同步

2026-11-22：默认启动已改为 Windows 原生，Python 和依赖全部留在项目目录；旧 `start-wsl` 入口转向新 Windows 脚本。下文 WSL 实测保留为历史对照，不代表 Windows 当前耗时；Windows 方案及验证见 [windows-native-startup.md](windows-native-startup.md)。首次下载环境与日常启动分开衡量。

## 问题分析（2026-11-20）

用户反馈启动需要 10 秒至几十秒。当前 Windows 脚本通过 WSL 启动 Uvicorn，没有重复安装依赖或启用热重载；主要阻塞在 Python 应用加载和应用生命周期内。

在当前 WSL 环境测得：应用导入 10.67 秒，其中 `app.budgets` 顶层引入的 `openpyxl` 占 8.76 秒。正式账本的隔离副本初始化约 0.24 秒，常用项每日快照约 0.012 秒。当天汇率尚未缓存，公开接口本次请求约 0.95 秒；原实现会在响应任何请求前等待该请求结束。网络超时设为 5 秒，但不是整次请求的严格总时限，不能据此保证启动上限。

这次测量不包含 Windows / WSL 冷启动，不以修改账本或跳过迁移换取启动速度。

## 处理规则

1. Excel 依赖只在实际导出时导入，预算两种导出入口与原流水导出保持相同策略。首次导出可能承担依赖加载耗时，同一进程后续复用缓存；表格内容不变。
2. 数据库初始化、必要迁移与常用项每日快照仍在服务就绪前执行，避免请求看到未完成的结构或不稳定的排序。
3. 当天汇率在生命周期管理的后台任务中补齐：先读已有快照，有记录即跳过；缺失时仅将公开网络请求交给可取消等待的工作线程。页面和记账无需等待联网；已有汇率继续使用原来的回退规则，没有汇率仍明确显示缺失。
4. 后台任务取消或服务关闭后，不再将该网络请求的结果写入数据库。工作线程只负责取数，不持有数据库连接；关闭不等待慢网络。错误写入日志，不使应用启动失败。
5. 后台同步期间允许手工录入或同步。自动请求返回后在短写事务内再次检查当天快照，不覆盖期间新写入的记录；只有显式 `force=true` 的同步继续允许覆盖。真实流水、预算归属和历史金额保持不变。
6. 启动日志分别显示数据库初始化、常用项统计耗时以及后台汇率同步结果，便于区分本地加载与联网等待。日常命令不启用 `--reload`，开发时可自行添加。

## 验证

- 使用独立 Python 进程验证加载应用不会导入 `openpyxl`，避免测试进程提前导入造成误判。
- 隔离账本覆盖慢联网时健康检查、首页选项和记账仍可使用，成功落库、联网失败、已有汇率跳过、手工记录不被自动结果覆盖，以及关闭后不写入。
- 相同隔离副本、相同模拟慢网络条件下，对比启动到 `/api/health` 可用耗时；回归原流水与预算 Excel 导出。
- 正式账本仅作为只读备份源，不用于写入测试。

## 实测结果

当前 WSL 环境、同一账本隔离副本，启动进程到 `/api/health` 可访问（两边均模拟公开汇率等待 5 秒后失败）：

| 测量项 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 应用模块加载 | 10.67 秒 | 1.27 秒 |
| 服务进程到健康检查可用（含模拟慢联网） | 13.20 秒 | 1.81 秒 |

模块加载与完整启动为分开测量，受文件缓存影响，不能逐项直接相加。修改后健康检查与账户选项在网络尚未返回时即可访问；关闭进程约 0.21 秒，不等待该模拟请求。以上不包含 Windows 唤醒 WSL 的时间，不作为所有机器上的固定耗时承诺。

`PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -v` 全部 158 项通过（109.21 秒），包括新增 8 项启动回归，以及原记账余额、冲销、预算、定存和 Excel 导出。真实 Uvicorn 进程对照试验与单元测试均未写入正式账本。

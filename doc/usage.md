# 本地使用说明

## 第一次启动

项目已使用 SQLite 初始化空数据库：

```bash
.venv/bin/python -m scripts.init_db
.venv/bin/python -m uvicorn app.main:app --reload
```

启动后在浏览器打开 `http://127.0.0.1:8000`。

数据库文件位于 `data/finance.db`。应用每次通过前端写入数据前，都会在 `backups/` 创建一个 SQLite 备份。

备份采用人工定期整理：保留最近 7 个自然日内创建的全部备份，并永久保留所有 `finance-pre-*` 迁移前备份；更早的普通 `finance-*` 备份及其 WAL/SHM 辅助文件可在确认保留项完整后删除。7 日范围按上海当前日期计算并包含当天。整理只影响恢复点，不修改正式账本、流水或审计记录。

## Windows 一键启动

在 Windows 文件资源管理器中双击 `scripts/start-wsl.cmd`。该脚本会通过默认 WSL 发行版启动服务，并自动将项目所在的 Windows 路径转换为 WSL 路径。

浏览器打开 `http://127.0.0.1:8000`。服务运行期间请保持脚本窗口打开；要结束服务，在该窗口按 `Ctrl+C`，或直接关闭窗口。

## 开始记账前

当前数据库已初始化人民币/港币现金、支付宝、微信、人民币/港币银行卡、券商账户和八达通账户，期初余额均为 0。可按 [database-manual.md](database-manual.md) 修改账户名称、机构和期初余额，或新增其他账户。

支付宝基金账户与花呗的记账规则见 [account-model.md](account-model.md)。

默认已创建 CNY、HKD、USD、EUR、JPY 五种币种，以及常用收入、支出分类。后续可直接在 `currencies` 与 `categories` 表扩展。

支出分类中，“食品杂货”统一用于早餐食材、生鲜、零食、纸品、清洁用品及其他食品或日用杂货；外食、外卖等即时餐食归入“餐饮”。“生活开销”用于洗衣、剪发、修鞋等日常生活服务。“日常购物”已取消，升级时会先备份为 `finance-pre-category-merge-*.db`，再把它的流水及相关引用改到“食品杂货”；旧“个人护理”原位改名为“生活开销”，迁移前备份为 `finance-pre-living-expense-category-*.db`。账户、金额和预算归属不变。

给他人发工资、支付劳务费或兼职报酬时，使用支出分类“工资/劳务支出”；本人收到工资或劳务收入时，使用收入分类“工资/劳务”。

银行、信用卡或支付平台因消费发放的现金奖励使用收入分类“回赠”。若退款后回赠被撤销，先把撤销金额记为真实支出，再将“回赠收入 + 撤销支出”组装为收入冲销事项；原消费和退款另建支出冲销事项。这样原始账户余额完整保留，冲销后统计分别得到净消费和净回赠。

## 当前前端能力

- 首页只提供记账：新增一笔支出、入账、同币种转账或跨币种换汇。保存成功后，支出显示支付账户余额，入账显示到账账户余额，转账与换汇同时显示两端最新余额；负债账户显示当前欠款。
- 首页左侧“便捷操作”从设置读取，可预填支出、入账、转账 / 换汇的账户、分类、预算、金额、对象和备注；点击后仍需检查并保存才会创建流水。旧账本原有的八达通餐饮、微信转八达通和支付宝定投会在首次升级时迁移。
- 支出、收入的单选分类全部放在同一个最多 8 行的滚动菜单中，按最近 45 天与 14 天的实际使用笔数加权排序；两类分别计算，当天内排序保持不变。
- 账户选择器顶部显示最多 6 个角色相关的优先账户；下方“全部账户”按国内银行、香港及境外银行、投资、现金与电子钱包、交通与储值、负债等目录展开，展开目录后直接选择账户。优先账户会在全部目录中再次出现，低频账户也不会被隐藏。
- 通过顶部“概况与查看”进入独立页面，按月份查看收入、支出、结余、资产、负债和净资产。
- 概况与查看页面包含按 CNY、HKD 换算的总资产、总负债和净资产，账户内资金流动、最近 20 笔流水和当前月份的 Excel 导出。
- 通过顶部“账户与流水”查看单个账户的期初余额、累计流入/流出、当前余额和流水；账户明细、流水查询默认当前自然月，各自保留筛选范围。可点“本月、上月、本季度、本年、全部、自定义”，按月/季度/年用前后期按钮翻看。快捷日期保留账户、预算、类型等其他条件；“重置筛选”恢复本月并重置其他筛选。日期只限制查询，账户当前余额始终按完整流水计算。
- 同页“流水查询”支持跨账户查询，并可同时勾选多个预算归属、多个流水类型、多个收入/支出分类。预算不勾选表示全部，勾选多个时按并集口径且每笔只计一次；因此可同选“日常预算”和“随心花”查看完整广义日常开支，也可单独勾选随心花。分类面板提供“全选支出”、“反选支出”和“清空”，用于快速查看指定支出分类或其补集；清空分类仍表示全部分类。筛选区下方显示全部命中流水的原币种流入/流出/净流动，以及按已保存系统汇率折算的 CNY、HKD 合计和各流水类型小计，分页不影响总额。“全部”或手动清空两端日期查询全历史，只填一端则按单边界筛选，均有金额汇总。分类项直接读取数据库，也包含已停用的历史分类。
- 当流水查询选择完整日期范围（不超过 12 个月）和唯一一种流水类型时，结果下方的“流水详情”会按 HKD 展示日历、每日金额直方图、每日均值/中位数/方差等统计，以及星期、分类和账户分布；缺少当天汇率时使用日期最接近的已保存快照。
- 每笔流水可在“账户与流水”页修改、删除或标记待核实；删除、修改、标记、对账、余额调整和期初余额修正都会先在 `backups/` 创建备份，并在数据库中留下审计快照。
- 账户摘要显示最近对账状态。账实差异无法拆回具体流水时，使用“对账 / 调整余额”；之后若查明差额是利息、回赠或漏记消费，可从最近对账进入当日调整流水，点击“确认用途”，改成普通入账或支出并选择分类。不要另补一笔相同金额的流水，否则余额会重复变化。建账日初始金额录错时，使用“修正期初”。
- 通过“投资与汇率”录入基金或券商账户总资产。系统会自动生成可查询的投资估值损益流水；修改历史估值会重算后续自动损益。
- 后端启动时会在当天缺少记录的情况下自动同步 USD/CNY、HKD/CNY 汇率。投资页也可手动同步或在必要时覆盖汇率；网络失败不会阻止本地服务启动。
- 支出模式默认选中“支付账户”常用排序第一项。排序同时考虑最近 45 天和最近 14 天的真实支出，计算为“45 天笔数 + 14 天笔数 × 5”；长期习惯用于稳定结果，近期使用变化权重更高。当天快照生成后不会反复变化，次日会纳入当天新增、修改或删除的流水。

多预算计划和栏目现在通过“预算计划 / 设置”维护；对账与投资估值使用已有页面。旧版 `monthly_budgets` 和兼容投资快照仍保留原维护方式。相关字段和约束见 [architecture.md](architecture.md) 与 [transaction-entry.md](transaction-entry.md)。

## 冲销与代收代付

1. 照常在首页录入每一笔真实收入和支出。
2. 打开第五页“冲销与代收代付”，点击“新建事项”，选择“支出后收回”或“收入后分出”。
3. 在上方选择多笔主流水，在下方选择多笔冲抵流水。选择器支持日期、账户、分类、对象 / 备注筛选和跨页多选。
4. 日期自动取全部成员最早日期；分类继承最早一笔主流水，同日按流水编号排序。不需要填写统计时期、分类或起点。新增、移除和修改原流水后自动更新归属。
5. 点击“预览净额”查看原币分项和 CNY / HKD 结果，保存后生效。以后可以继续加入新记录，或移除已有关联。

概况页和账户与流水页的“流水查询”提供“原始收付 / 冲销后收支”切换，各页面分别记住自己的选择，初次默认原始口径。第三页还可选择“仅冲销事项（页面5）”，查询第五页组织的事项，也可直接打开第五页。冲销模式按自动归属的日期和分类统计；普通未关联流水在结果中只占一行，冲销事项才展示净额详情并可展开成员。“涉及账户”命中后返回整个事项，不代表该账户实际流入 / 流出。展开事项可查看全部原始成员，包括其他日期、月份或账户的收付款。

支出冲销金额为支出减收回；收入冲销金额为收入减分出。允许零值、负支出和负收入，不要求两边相等，不设结清状态。跨币种按每笔原始日期的已保存汇率换算，缺当天快照时使用邻近快照；缺少任一成员的换算条件时，整个事项在该计价币种下显示“无法完整换算”，合计明确显示覆盖缺失。

“移除关联”或“解散事项”只改变统计关系，不删除原始流水。仍有关联的流水不能直接删除；先移除关联或解散事项，再从流水页删除。编辑原始金额后事项立即重算，编辑日期或分类也会更新事项归属。

Excel 跟随概况页所选口径，新增“个人收支”“冲销事项”“冲销关联明细”；关联明细包含完整成员。冲销模式另保留“原始月度总览”“原始月度预算”，账户余额、交易流水和内部资金流动始终保留原始记录。冲销模式预算按预算币种折算命中类别的完整记录，原始模式预算仍按原币种统计。

第一次启动新版本时，会先为已有账本创建 `finance-pre-offset-*.db` 备份，再添加事项表和审计约束。现有流水不会自动分组，需要自行选择。

## 定期存款

在首页点“存入定期”，或打开“定期存款”页点“＋ 存入定期”。选择实际扣款账户，填写本金、存入日期、按月/按天期限及预期年利率（例如 `3.5` 表示年利率 3.5%），币种随账户确定。系统自动计算到期日；月末存款在目标月无同日时取月末。银行合同日期不同可填“银行到期日更正”，计息基准可选 365 / 360 天。

保存后，流动账户减少、本金进入定存资产，净资产不因本金移动而减少。预期利息是按实际天数的单利估算，尚未进入收入、预算或资产。统一表格按到期日排列，可按银行账户、币种、状态查看，顶部按币种显示存续本金及 30 天内到期（含已到期待到账）的本金。日期到期只改变提醒状态，不自动记账。

本金利息实际返回后，在对应行点“确认到账”，填实际日期、同币种到账账户和实际利息（提前全额取出也可，利息可填 `0`）。系统同时记录本金回流和“利息/股息”收入；实际利息可随后在预算页分配。续存时先确认这笔到账，再新建下一笔定存。首版使用全额本金回流；部分支取、不同币种结算需另外整理真实资金路径。

存续定存可直接修改；录错时删除会同时撤销存入转账、恢复来源余额。已到账记录需先“撤销到账”再更正；如果利息已经分配预算或加入冲销事项，先移除这些关联。账户与流水中可追溯本金和利息，点击“定存记录”进入维护。补录历史时确认同一笔本金没有另记过转账，避免重复扣款。预算里的“定期”仅表示用途安排，需按自己的计划另行调拨。

首次升级先创建 `finance-pre-term-deposits-*.db`，不自动移动任何资金；首次存入才建立零期初定存汇总账户。Excel 新增截至报告日的“定期存款”表。

## 第六页预算计划与设置

预算新增额度由收入分配自动汇总，支出继续单选预算，正负结余连续结转。预算用途、公共存储目录和默认项在“设置”维护；每个预算系统仍只有一种币种。

1. **记收入并安排用途**：在首页入账时，“收入全额分给”可将本笔收入全部安排给一个预算；也可勾选“按金额拆分到多个预算”，逐行填写预算和金额。拆分金额使用该预算的币种。暂时未想好用途时选“暂不分配预算”，以后补充；真实收入与本次分配一起成功或一起回滚，不会只保存一半。
2. **之后补充或修改**：第六页点击“分配收入”，搜索普通收入或收入冲销事项。弹窗展示净收入、已分配和剩余，可以添加、修改、移除预算行；移除全部行表示取消该来源分配。新增默认归来源统计月份，也可明确安排其他月份。保存前显示折回来源币种的占用与余额，禁止超过来源净收入。成功关闭弹窗；失败保留草稿，取消或 Esc 遇未保存改动会确认。
3. **多来源自动合计**：一笔工资可分给多个预算，同一预算同月也可接收多笔工资。预算页“本月新增”自动合计这些分配，不能再单独修改收入模式的总额。例：工资 A 分日常 600、工资 B 分日常 200，则日常新增为 800；同月净消费 100、上月结余为零时，剩余为 700。
4. **再安排存储**：月度列表点击“安排存储 / 查看来源”，总额只读，下方维护活期、定期、ETF 等分配。可以先不安排存储，额度自然留在预算内“待分配”。从其他月份复制时，收入模式只复制存储安排，不复制收入额度。总表仍可切换截至所选月剩余、所选月预算、累计安排；支持一级汇总、交换行列和来源追溯。
5. **跨币种与改币种**：预算币种未设置时首次分配继承来源币种。已有币种则按已保存的来源参考日汇率折算占用，界面展示各行币种；全额分配按目标精度向下取整，不能由尾差导致超配。修改预算币种仍保留可见数字，同时重新核验全部来源，金额精度或额度不符会整体回滚。
6. **支出与结转**：日常支出默认日常预算，专项支出单选对应预算；本月没有新收入也能记账并产生负结余。月末不必复制余额：上月结余＋本月收入分配－本月净支出自动传到下月。消费和存储调拨不会释放已占用收入，不能把已花掉的工资再次分配。
7. **核对与导出**：第三页原始口径保持真实到账金额，并单列匹配来源分配给所选预算的已核实收入合计；同一事项的多笔到账只计一次分配。指定预算的冲销口径只计实际分配份额，没有分配的旧收入标签不再自动计作收入，取消全部分配后为零；旧标签仍可用于原始流水筛选。流水编辑弹窗提供“查看 / 修改收入预算分配”；修改收入标签不等于转移分配。预算 Excel 保留已记录金额，另外标示已核实分配、来源日期和状态。

第三页日期筛选按收入发生日／事项统计日，第六页“本月新增”按预算生效月份计算。比如十月收到 1,000，分给十月 400、十一月 600，第三页十月会查到这个来源的全部分配 1,000，第六页两个月分别新增 400 和 600。在查询汇总展开“查看收入来源与预算生效月份”，可以查看对应关系，点击月份跳转该预算该月。

“收入尚可分配”是尚未分给预算的收入余额；预算内“待分配”是已经属于该预算但尚未安排存储的金额。两者分别在来源弹窗和存储总表展示，不新增“待定存储”栏目。

**不用手算最后一行**：首页拆分入账和第六页分配弹窗中，每行金额下都有“全部剩余”。先填其他预算金额，再为接收余款的预算勾选它（最多一行）；系统先扣除其他行占用，再自动换算到该预算币种。弹窗会显示自动金额及最终来源余款，修改其他行会重新计算；首页在保存入账时计算。切换勾选会恢复前一行手填金额，保存后记录固定分配金额，不会随以后汇率变动自动增减。跨币种最小单位无法整除时保留极小尾差；无剩余、余款不足目标最小单位或缺汇率时提示调整，不会超额保存。

收入冲销事项只使用扣除分出后的净收入，事项中的单笔收入不能重复分配。AA、退款等支出事项的回款只减少原预算消费，不作为新的预算收入。自己承担的房租、学费若希望纳入预算消费，应保留为个人支出；已经冲减净收入的分出不能再次扣预算。

修改收入、冲销成员或汇率后会重新核验资金来源；若净收入已小于分配额度，预算结余显示未完整并提示来源缺口，真实流水纠错仍可保存。第三页预算收入汇总和图表会排除无效分配、显示来源提示，追溯明细仍保留已记录金额；不筛选预算时的真实个人收入照常计算。可以逐项减少原分配直到修复，系统不会擅自缩减各预算。收入要加入事项、被删除，或收入事项要解散、改方向时，先从分配入口核对并移除旧分配，再选择完整事项重新安排。修改来源日期后已明确的分配月份保持不变，应在分配窗口核对。

**历史数据升级**：启动前创建 `finance-pre-income-allocations-*.db` 备份。旧预案中已绑定的来源转成等额分配，原月份、存储安排和历史版本保留；没有绑定来源的预案继续显示为“历史手填 · 待核对来源”，不会根据旧收入标签推断金额。为其补认领来源时，在分配弹窗勾选“替代历史手填总额”，以分配合计替代旧值，不能两者相加。原存储安排保留；调小总额后若存储超额，需再调整存储。若新入账遇历史预案冲突，可先暂不分配保存收入，再从预算页补分配并核对替代。

**跨月历史额度也要核对**：分配窗口会列出目标预算中其他月份尚未核对的手填额度。如果旧额度来自本次工资，选“替代重复额度”，旧总额归零、新分配照常生效；旧存储安排和版本保留，可随后调整。如果旧额度确实属于另一笔独立资金，选“保留为独立资金”。同月旧预案只能替代，不能叠加。核对状态跟随旧预案版本，修改后需重新核对。已有新收入与未核对旧额度同时累计时，结余暂显示未完整，核对后恢复；系统不会替你判断或删除旧额度。此次升级先备份为 `finance-pre-budget-review-*.db`。

期初预算结余继续在“设置 → 预算系统 → 编辑”维护，用于承接建账前的存量；不伪造收入。执行起点默认最早相关预算或支出月，也可明确设置起算月份。结转历史可逐月查看；累计起始月只影响计划总表筛选，不清空以前的结余。

### 维护存储剩余

1. 在交叉总表选择“截至所选月剩余”，点击预算旁的“管理”，进入“默认扣款”，可为每个预算选择活期等默认消费存储。它作用于该预算所有未单独指定的消费，包括历史月份；以后日常记账只需像原来一样选择预算，不必每笔再选存储。没有设置默认时，系统先用“待分配”正余额，再用启用的顶级“活期”正余额；两者不足的差额才列为“待归属消费”，不会自动动用定期、ETF 或股票。没有明确原存储的负净消费回补待分配。
2. 特殊消费进入“特殊消费”页签，点击“改归属”后选其他存储；也可选“使用本预算默认扣款”恢复自动规则。列表显示所选月份的完整支出事项净额，AA 返还不会重复成为收入；负净消费回补该存储。其他月份在关闭弹窗后切换第六页月份查看。事项重新组织或改变预算归属后，应核对新事项的扣款位置。
3. 明确选择默认存储或单独归属后，活期等余额不足时会显示红色负数。在“存储调拨”选转出、转入存储和金额即可补足；“待分配”也可以调入具体存储。未指定消费的自动顺序只会把待分配和活期扣到零，差额继续留作待归属。转出额不能超过转出项剩余；缺汇率或仍有待归属差额时先整理，再调拨。
4. 存储逐月结转，当月先加入预算、扣消费，再做月末调拨；调拨不会让以前的消费重新改扣其他存储，下月承接调整后的余额。例如活期安排 100、消费 50，再调拨 50 到待分配，结果就是活期 0、待分配 50。调拨支持修改和撤销，只调整预算额度；真实提现、卖出或转账仍按实际发生记账。后续月份新增的待分配或活期额度可吸收以前待归属的缺口。不要通过减少历史新增预算总额来表示消费，也不用下月重新录入已结转余额。期初预算结余先进入“待分配”，再按需要调往各存储。
5. 存储剩余不代表账户资金或 ETF 实时市值。累计起始月不会截断剩余；缺汇率或跨预算事项显示“未完整”。改正预算币种会连同调拨保持可见数字、重新检查精度。Excel 追加“存储剩余”“存储调拨”，原计划及执行表继续保留。首次升级前自动备份为 `finance-pre-storage-balances-*.db`。

“待定存储方式”已统一到“待分配”：以后尚未决定存储去向时只填写预案总额，不新增存储明细。升级会将当前计划中的待定存储金额退回待分配，保留预案总额及历史版本；已明确分配到活期、定期、ETF、股票等真实存储的金额不变。升级前备份为 `finance-pre-unallocated-storage-*.db`。

## 给记账选择预算归属

首页支出、入账、转账有各自独立草稿，切换不会清空其他模式；刷新页面仍会丢弃未保存草稿。支出单选“预算归属”，入账支持全额或按金额分配预算，转账和换汇不计为预算消费。

电脑端的保存按钮位于字段上方，并会在向下填写时保持可见。金额及其他数字必须直接填写；鼠标滚轮只滚动页面，不会再把获得焦点的数字误增减，页面也不显示数字框的增减箭头。原有金额精度和有效范围校验不变。

首页保存支出后，右上角成功提示会同时显示支付账户的最新余额，可直接与银行或钱包核对，无须切到“账户与流水”。信用卡等负债账户显示当前欠款余额。

自动预填顺序为：**本笔手选 → 命名预设 → 分类映射 → 模式默认**。支出不单独指定时计入日常预算，收入可暂不分配。入账预设指定预算时，普通全额模式会把收入分给该预算；按金额拆分时使用分配行。手选结果不会被后续分类切换覆盖；点击“恢复自动预算”可重新套用规则。保存专项消费后，下一笔重新应用默认或分类规则。

两份工资可在“设置 → 收入 / 支出预设”建立“工资 A / 工资 B”，分别指定预算，按需预填分类和到账账户。学费、劳务支出等可在“分类映射”指定预算，不需要改账户或把真实分类复制多份。新设置只影响后续预填，不会重写历史记录。

首页按钮在“设置 → 首页便捷操作”维护。点击“新增便捷操作”后选择模式，再填写该模式需要的账户和分类；预算留空时沿用当前自动规则，金额也可留空等待每次记账填写。卡片可上移、下移、编辑、停用或删除。停用不会删除模板，删除模板也不会删除任何流水。

查看日常消费：进入第三页“账户与流水 → 流水查询”，同时勾选“预算归属：日常预算 + 随心花”、“类型：支出”和完整日期范围后查询，即得到包含自由消费的广义日常开支；只勾选随心花则可单独看这个心理安心额度。明细、分页总数、汇总及图表均应用同一组预算筛选。**以前及今后未单独标注的支出都自动计入日常，只需将少量非日常消费改为专项预算。**明细显示“日常预算 · 自动”，编辑时选择“日常预算（自动）”可清除单独标记并恢复日常归属。

更改新增记账的预填项，不改变旧流水的有效归属。日常预算即使改名，关联也保持。只有明确更改设置中的“未单独指定的支出计入”时，所有未标注支出才会一起改按另一预算统计。收入、转账、换汇和调整不因这条规则变成日常消费。

冲销口径下，一个事项的全部主方向流水属于同一预算时，整个净额归该预算，冲抵方即使在其他月份或标了其他预算也会完整参与计算。主方向跨预算时，单预算统计显示未纳入事项的提示及入口；查询全部预算仍只计一次。此时需要检查主流水归属或重新组织确实可分开的事项，不自动分摊金额。

第一次安装预算功能会在添加字段前备份为 `finance-pre-budget-*.db`；已有预算功能升级到日常自动归属规则时，备份为 `finance-pre-daily-budget-*.db`。原流水金额和单独标记不变，日常归属在查询时计算。开发测试未改动正式账本；若服务仍运行旧进程，请关闭后按原启动方式重新启动，再刷新浏览器。

## 验证

运行以下命令执行隔离冒烟测试；测试使用临时数据库，不会修改 `data/finance.db`：

测试依赖见 `requirements-dev.txt`（包含 HTTP 接口测试所需的 `httpx`）；未安装时先运行 `.venv/bin/python -m pip install -r requirements-dev.txt`。

```bash
.venv/bin/python -m unittest discover -s tests -v
```

浏览器回归使用 `tests/budget_browser_server.py`，它只在临时目录创建隔离账本并在 `127.0.0.1:18110` 启动服务，不同步正式汇率。安装 Playwright/Chromium 后，在另一终端运行 `node tests/income_allocations_browser.cjs`，覆盖桌面收入拆分、超额草稿保护、自动总额、存储编辑、流水分配入口和历史替代确认。脚本先校验隔离标记，拒绝操作正式服务；重跑前重启隔离服务以获取干净账本。测试后按 Ctrl+C 停止服务，临时数据库自动清理。

`node tests/term_deposits_browser.cjs` 使用同一隔离服务验证首页存入、原草稿保留、到期及利息预览、表格筛选、编辑、提前到账、撤销与删除，并核对原账户余额恢复。后端 `tests/test_term_deposits.py` 覆盖定存对现金、净资产、预算及导出的影响、版本冲突、关联保护和迁移备份。

`node tests/budget_consistency_browser.cjs` 使用同一隔离服务验证跨月历史核对、来源日期与生效月份跳转、无效来源提示和消费后调拨，可独立运行，也可在收入回归之后顺序执行。重跑该脚本同样需重启隔离服务。后端收入分配与存储测试覆盖取消分配不回退标签、跨月替代回滚、独立资金版本失效、新旧未核对额度并存、查询／导出完整性及逐月存储扣减。

`tests/test_income_allocations.py` 覆盖多来源合计、原子回滚、并发令牌、净收入与 AA、跨币种、历史替代与迁移、来源减少、筛选及导出。原手填计划与绑定接口的兼容性继续由 `test_budgets.py`、`test_budget_funding.py`、`test_budget_storage.py` 检查；原手填预案相关的浏览器脚本保留旧交互记录，新收入流程以 `income_allocations_browser.cjs` 与 `budget_consistency_browser.cjs` 为验收入口。`accounts_dates_browser.cjs` 继续覆盖日期快捷操作。

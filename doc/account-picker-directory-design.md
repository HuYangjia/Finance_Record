# 账户选择器全量目录设计

设计日期：2026-10-18。状态：已实现。

## 背景与结论

当前账户选择器先显示最多 6 个常用账户，其余账户集中在一个“其他账户”区域。账户达到 27 个后，频度排序仍适合快速选择高频账户，但低频账户缺少稳定的查找路径。

本轮只调整账户选择器的组织方式，不增加账户启停、删除或资料维护页面。确认后的结构是：

1. 顶部继续显示最多 6 个优先账户，沿用现有角色相关的 45 天 / 14 天加权规则。
2. 下方显示“全部账户”目录，包含所有当前可选账户。
3. 优先账户在“全部账户”中再次出现；两处是同一个账户 ID，不产生副本。
4. 全部账户按“业务目录 → 机构 → 账户”展开，目录内使用稳定顺序，不随每日频度变化。

## 一、目录模型

新增 `account_directories` 目录表：

| 字段 | 含义 |
| --- | --- |
| `key` | 稳定主键 |
| `name` | 前端目录名称 |
| `sort_order` | 目录顺序 |

`accounts.directory_key` 保存账户所属目录，可空外键。内置目录顺序为：

1. `domestic_bank`：国内银行账户。
2. `overseas_bank`：香港及境外银行账户。
3. `investment`：投资账户。
4. `cash_wallet`：现金与电子钱包。
5. `stored_value`：交通与储值账户。
6. `liability`：负债账户。
7. `other`：其他账户。

目录只描述选择器中的位置，不改变账户类型、资产负债属性、币种、投资语义、余额和统计。机构继续使用账户现有 `institution` 字段，作为第二级；账户本身是第三级。机构为空时显示“其他机构”。

首次迁移在 `finance-pre-account-directories-*.db` 备份后写入目录元数据，并只给尚未归类的账户补充目录：

- 负债账户归入“负债账户”。
- `investment_asset`、`broker_cash` 归入“投资账户”。
- `cash`、`e_wallet` 归入“现金与电子钱包”。
- `transit_card`、`prepaid_card` 归入“交通与储值账户”。
- 已知境内银行机构归入“国内银行账户”。
- 已知香港及境外银行机构归入“香港及境外银行账户”。
- 无法判断的账户归入“其他账户”，不根据币种猜测开户地区。

迁移不覆盖已经明确填写的目录；重复初始化不会重写用户后续调整。

## 二、选择器结构

账户选择器打开后依次显示：

```text
优先账户
  最多 6 个角色相关账户

全部账户
  国内银行账户（6）
    中国建设银行（2）
      建设银行（人民币） · CNY
      建设银行（美元） · USD
  香港及境外银行账户（5）
  投资账户（6）
  现金与电子钱包（4）
  交通与储值账户（4）
  负债账户（2）
```

交互规则：

- “全部账户”始终显示，不再叫“其他账户”；即使没有任何近期流水，也能从目录找到全部选项。
- 一级目录和机构使用可点击的折叠按钮，显示所含账户数；展开不会关闭选择器。
- 选择任一叶子账户后写回原生 `select`、触发原有 `change` 事件并关闭菜单。
- 同一个账户可以同时出现在优先区和目录区，两处都显示当前选中标记。
- 打开选择器时，如果当前账户不在优先区，自动展开其目录和机构并把目录中的账户滚入可见区域；若它在优先区，焦点落在上方副本。
- 关闭选择器后折叠状态重置，下一次根据当前选中账户重新展开。
- 键盘上下键按当前可见按钮移动；`Enter` 或空格展开目录或选择账户；`Escape` 关闭并返回触发按钮。

目录菜单设置最大高度并内部滚动，不能随账户数量把表单整体拉长。

## 三、排序规则

优先账户继续沿用现有规则：

```text
分数 = 最近 45 天笔数 + 最近 14 天笔数 × 5
```

支付账户、到账账户、转出账户、转入账户和综合账户分别使用原有活动角色，最多取有近期记录的前 6 项。

全部账户目录采用稳定顺序：

1. 目录 `sort_order`。
2. 机构名称，使用中文本地排序。
3. 币种代码。
4. 账户名称。
5. 账户 ID。

这样高频区可以随使用习惯变化，目录查找位置保持稳定。

## 四、接口与适用范围

`GET /api/accounts` 为每个账户增加：

```json
{
  "directory_key": "overseas_bank",
  "directory_name": "香港及境外银行账户",
  "directory_sort_order": 20,
  "institution": "ZABank"
}
```

缺少有效目录时按“其他账户”返回，保证旧数据和未归类账户仍可选择。

目录模式应用于所有已经使用常用账户组件的单选账户控件：

- 首页支付、到账、转出和转入账户。
- 第三页账户明细账户、流水查询账户、历史流水编辑来源与去向账户。
- 第三页对账、余额调整和期初修正所复用的账户控件。

设置页便捷操作弹窗、预算预设、冲销筛选及投资页当前仍使用原生下拉框，本轮不强行替换；它们继续读取相同账户 ID 和名称，不受目录字段影响。

## 五、兼容性与验证

- 不修改 `transactions`、投资估值、预算、冲销成员或账户金额。
- 原生 `select` 仍保留，表单提交、必填校验和 API 参数不变。
- 已停用历史账户在编辑旧流水时仍按现有兼容规则显示；若目录缺失进入“其他账户”。
- 目录迁移前创建备份，迁移后检查业务表行内容、外键和数据库完整性。

验收标准：

1. 每个账户选择器最多显示 6 个优先账户，并保持角色相关排序。
2. “全部账户”目录包含当前控件中的所有账户，包括已经出现在优先区的账户。
3. 目录、机构、账户三级能够展开，数量和选中状态正确。
4. 非优先账户打开时自动展开所在路径；选择后原有记账、查询和编辑逻辑正常。
5. 目录内顺序不受当天新流水影响；优先区仍使用每日快照。
6. 正式账本现有账户完成预期归类，流水、余额及统计结果保持不变。

## 六、实现结果

- 已增加账户目录表及账户目录外键，首次升级自动备份和归类，重复初始化不覆盖已有归属。
- `/api/accounts` 和投资账户接口已返回目录、机构与稳定顺序信息。
- 首页及第三页的账户单选组件已切换为“优先账户 + 全部账户三级目录”；原生下拉值和业务接口保持不变。
- 隔离测试覆盖旧库迁移、预期归类、未知机构回退、用户归属保留、备份幂等、完整性和外键检查。
